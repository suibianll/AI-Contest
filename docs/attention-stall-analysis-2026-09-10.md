## 摘要

Attention 侧占可加模型缺口分配的 78%，却在累计 **22 次官方超时**之后只兑现 **+21 分**。诊断结论是四层问题同时成立，且每层都有硬证据：

| 层 | 问题 | 证据 |
|---|---|---|
| **空间层** | 天然参数化是**规范变换**，一阶精确不可见；能得分的只剩非规范残差 | 精确零变分恒等式；STE 穿部署编码梯度 ~1e-15 被 Adam eps=1e-8 吞掉；表达力梯度 0 / 0 / +22 / +29 |
| **目标层** | 训练 loss、门 loss、接受判据是**三个不同函数**，量化器都不同；门只查 1 个窗口 | `solution.py` 11415 / 11507 / 11559 / 11558 |
| **成本层** | 校准是约 **3300 次前向的搜索**，且拿 5 个窗口（Linear 拿 2 个、零前向） | 常量推出的结构计数；`official_eval.py:2584` vs `:991` |
| **测量层** | 本地面板**双向反预测**，官方提交是唯一仪器 | 8 个反转实例，含 A23 / A25 一对双向反转 |

与 Linear 对照最清楚：Linear 在这四层里占了三层好牌（精确下降恒等式、本地可预测、零前向成本），所以它能靠「减少派发数」把 +375 装进余量。Attention 四层全占坏牌——它的每一个动作都同时受制于「方向可能是零」和「代价一定是正」。

**本轮新增口径收紧：21071 源码不可得。** 该机制此前是本项目唯一有外部官方数字绑定的锚点。源码不可得意味着「复现外部机制」这条战略路径关闭，且缺口分解的目标值失去来源（见 §0.3）。

## 4. 四层诊断

### 4.1 空间层：规范不变性陷阱

这是最深的一层。`logs/execution/continuous-attention-anchor24-a1.md` 记录了一个精确恒等式：

```
logits = x_q · exp(S) · exp(−S) · x_kᵀ  ≡  x_q · x_kᵀ
```

**一阶变分精确为零。** 注意它与 Linear 的 L-EM 恒等式性质完全相反——L-EM 的 `L(X) = J(X) + const` 是**下降**恒等式（有精确梯度可走）；这个是**不变性**恒等式（梯度精确为零，无处可走）。

`logs/execution/2026-09-10-attention-agr2-trueobjective.md` 从反面把它钉死：**STE 穿过完整部署编码后的梯度量级 ~1e-15，被 Adam 的 eps=1e-8 直接吞掉**——所以「amax 尺度比代理目标」是承重的，优化器优化的从来不是真实部署目标。

于是官方确认的那条**表达力梯度**根本不是「效果递增」，而是一条**规范不变性足迹**：

| 机制 | 矩阵族 | 官方侧分 |
|---|---|---:|
| v190 逐通道闭式互逆平衡 | 对角 | 0（精确零） |
| v191 块三角输运（rank-1, N²=0） | 三角 | 0（精确零） |
| v192 全对称零迹残差 | 对称全矩阵 | +22 |
| A-GR1 一般非对称互逆 | 一般矩阵 | +29 |

**矩阵族越一般，非规范（可见）子空间越大，分数才从 0 爬起来。**

这一并解释了那一大堆「精确零」结果——v190 / v191 / v194 侧分 14405 逐位相等、A-QC1 72/72 全零、A-GR2 72/72 全零、v217 / v218 / v219 各 0/0/12、raw source-scale 与变换坐标对齐各 0/0/16。它们不是「幅度小」，是**在规范方向上搜索，部署输出按构造不变**。

> **关键推论**
>
> Attention 的问题可以更精确地重述：**它的搜索空间绝大部分是要花校准秒数、却在一阶上精确不可见的规范方向。** 这比「时间墙」更根本——即使余量充足，走规范方向也是精确零分。
>
> 于是「低天花板」和「高成本」不是两个独立问题，是**同一个规范结构的两个面**：能得分的非规范残差（对称 +22、一般矩阵 +29），恰好是校准成本最高的那一档。

### 4.2 目标层：训练、门、判据是三个不同的函数

| 环节 | 量化器 | 口径 |
|---|---|---|
| **训练 loss**<br>`solution.py:11415` | `_dense_to_hif4`，`search_offsets=None`<br>（单候选、无 importance、无 refine） | `residual².mean() / mse_std`（归一化代理） |
| **门 loss**<br>`solution.py:11507` | `hif4_dynamic_quantize_q/k/v`<br>（5 个 offset 候选 + importance + refine） | `(player − reference)².mean()`（未归一化原式 MSE） |
| **接受判据**<br>`solution.py:11559` | — | `player_mse / max(standard_mse, 1e-12)`（比值） |

**同一个窗口的 Q/K，在训练和门里走的是两个不同的量化器。** 训练还在 11425 处把量化器 Jacobian 当恒等（`grad_rotation = einsum(q_raw, d_qhat) + …`，docstring 自己写着 "Analytic-gradient trainer: no autograd"）。

所以「训练/部署不一致」不是「前向写法不一样」这么轻：**优化器在最小化 X，门在测量 Y，判据在比较 Y_cand / Y_parent，而 X 和 Y 连量化器都不是同一个。** v230 A-FIX1 只把前向对齐了、没对齐量化器与口径，本地反而 −0.004884——现在这条有了明确解释。

更尖锐的是 **11558 行 `gate_window = calib_qkv_list[-1]`：接受门只检查最后一个窗口**（长度 1024）。而训练用的是 `windows[:-1]`，即另外 4 个窗口。**训练在 4 个窗口上学，门在训练没见过的第 5 个窗口上判。**（A-GR1 的门是 2 个窗口 `(3, 4)`，稍好。）这正面解释了 v229 的本地 +0.014923 → 官方 −2：单窗口接受本身就是欠验证的。

### 4.3 成本层：Attention 是搜索，Linear 是公式

| 侧 | 校准窗口数 | 窗口长度 | 出处 |
|---|---:|---|---|
| **Attention** | **5（全部）** | 10 / 128 / 512 / 1024 / 1024 | `official_eval.py:2584`、`proxy_v3_eval.py:124` |
| Linear | 2 | 10 / 128 | `official_eval.py:991`、`capture_qwen35.py:92` |

Attention 从第一步就站在 2.5× 的窗口基线上，且其中两个是 1024 token。按源码常量推出的每层结构计数（**是计数，不是计时**）：

- **A1 选择轨**：~21 个候选 × 5 窗口 × 2 前向 ≈ **210 次前向 + 210 次编码**
- **选择后置门**：~20 次 `_attention_deployed_mse` × 5 窗口 × 2 前向 + 2 次部署量化 ≈ **200 次前向 + 200 次部署量化**
- **A2 训练**：`_A2_TRAIN_STEPS=32` × 4 窗口 + 8 次准备 ≈ **136 次小前向 + 同等次数手写反向**，外加 **≈481 次 `torch.linalg.solve`（批量 4×256×256）/层**
- **A2 门**：**8 次 1024-token 全窗口前向**（单次最大：1024×1024×16 heads）
- **合计：单层 ≈ 550 次前向量级 × 6 层 ≈ 3300 次**

对照 **Linear `_em1_*`（行 11948–12249）：零次前向。** 只有 `_dequantize_*` 取稠密矩阵 + `mm` + Cholesky 求逆 + 2 pass × 16 group 的块代价 einsum，全部在**已缓存张量**上做矩阵代数。

**这就是成本刚性的来源**：Linear 的一个机制加的是矩阵算子；Attention 的一个机制乘进的是一个已经 ~3300 次前向的搜索结构。

> **解开一个旧疑团**
>
> v205「本地校准砍 30% → 官方只省 6 秒」的原因找到了。C76.4 是 12 个旋转候选，住在**选择轨**（~210 次前向）。而真正贵的是**门轨（~200 次前向 + 200 次部署量化）和 A2 训练（136 次前向 + ~481 次 solve）**。砍掉选择轨的一大块，在总量里只占小头。
>
> **结论：要让 Attention 变得可负担，必须打门轨和训练器，不是打搜索候选。**

### 4.4 测量层

见 §3.3 的八条反转。对执行的含义很直接：既然本地读数在两个方向上都不预测官方，筛选候选就只能靠**机制级论证**（是否可证减少实际工作、是否可证保持输出），而官方提交槽位是最稀缺资源——本轮 22 次超时就是它的消耗记录。

> **怎么读这个结果**
>
> 三层结论必须分开，不要混：
>
> 1. **等价性：通过。** 72/72 逐位相同，含唯二 arm 的两层；六层真实数据 + 三条边界路径 control 全过。
> 2. **去重：成立。** gate 窗口对 15/15 轮、效应全正、sham ≈ 0。
> 3. **量级：不足，且差得远。** 约 0.2s 对需要的约 12s。
>
> 所以 A-CT1 **不是**「机制无效」，也**不是**「实现失败」——它是**一个被正确地做完了、但结果无关紧要的优化**。按本项目的裁决语汇应记 **NO_EFFECT（对目标而言）**：等价性成立，但它省下的工作不足以改变 v236 的官方结局。
>
> analyzer 六片全给 `decision: reject`（判据是 `delta_mean > 0`），这是**纯去重卡的正常读数**，不是失败信号。同样，`cand_api_6shard = 33.0s` vs `base_api_6shard = 2.40s` 是缓存态假象（候选五片冷、基线全程热），**不可比，也不表示 A-CT1 更慢**。
>
> 计划的 §5 预登记过「v236 若超时，只关闭原执行结构，不自动关闭已实质削减计算的 A-CT1」——那个条款的前提是削减**可能具有实质量级**。现在实测 0.58%，前提不成立。**该条应据此改写，而不是机械照搬。**

> **对 A-GR1 的重新定位**
>
> A-GR1 值 +29 分，代价约 +20.7s，手上 9s。此前日志的结论是「先把秒数腾出来再落地 A-GR1」——那句仍然对，但本卡证明了一件更具体的事：**腾出来的秒数不可能来自 A-GR1 自己的 gate。** 把它全部可去重的部分去掉，也只值 0.2s。
>
> 那 12s 只能来自别处（Linear 侧，例如 L-TF1 并入根）。否则 **A-GR1 在现根上不可落地**；继续在 Attention 门轨/训练器上找去重，是一个收益已被测定的方向。

**A-CT2**（`_agr1_train` 末尾统计复用）：冗余已由 §5 证据确认（同一变换与 loss 算 3 遍），但**量级比 A-CT1 更小**——它省的是训练**末尾**两遍标量重算，而 A-CT1 省的是 gate 里真实的前向与解码，后者实测只值 0.2s。**不建议为此开卡。**

>
> 在 21071 已不可得的现在，第三条实际上指向「不再推进」。

### 6.3 建议排序

1. **先存时间，再花钱。** 唯一无风险的动作是「等输出、少计算」的纯降时候选。v237（L-TF2）已归档、待官方裁决；计划中仍标注的未兑现项是**「L-TF1 尚未并入根 v231」**——v233 只在 v230 / K=1 父上测过，而官方已给它干净的 −4s。
2. **花钱只买 L-EM 类**——全项目唯一有官方收益记录、且本地读数可预测官方的机制类别，必须配降本调度（组号主序、梯度复用），不做参数邻域扫描。
3. **不按缺口比例分配投入。** 78% 这个数来自可加模型的**分配假设**，不是测量；其来源文档自己标注「顶端换算不可靠，仅量级参照」，而现在连锚点源码都没有了。
4. **Attention 的「去重」方向收益已测定，可以收手。** A-CT1 实测省约 0.2s（§6.2），A-CT2 量级更小。两者都**正确地**减少了真实存在的重复工作，也都**不足以改变任何官方结局**——去重打得再准，补不上 12s 的账。若要继续 Attention，只能回到**参数化层**（下一条），而不是继续找冗余。
5. **真正的出路在参数化层**：需要造出**非规范方向**，即让部署输出在参数移动时按构造改变。这是唯一未被证伪、且不依赖 21071 的方向。判据应当是可证伪的：新参数化必须在**一阶上有非零的部署输出变分**，否则一进门就是精确零。

> **对预期的一句实话**
>
> A-CT1 的两半问题现在都有了答案，且方向相反：**输出可以证明（72/72 等价通过），秒数实测不够（约 0.2s 对需要的约 12s）。** 这类纯去重卡的常见结局正是如此——能被证明的往往是无关紧要的那一半。
>
> A-GR1 因此在现根上**不可落地**，除非那 12s 从 Linear 侧腾出来；A-CT2 更小，不值得开卡。**Attention 的官方账本停在 +21，缺口 3244 不变。**
>
> 在 21071 源码不可得的前提下，本项目目前的证据不支持「可以在剩余余量内追平榜首」这一判断。
