## 2. 拟合可行性的定量判定

### 2.1 逐 case 特征 + LOO：定量拟合失败

因变量 = **官方侧向贡献差分**（由侧隔离实验解出，见 §3）；特征 = 本地 default panel
的逐 case 配对统计量。样本 18 个配对（11 Linear + 9 Attention，含 2 次结构性大跳）。

| 特征组合 | LOO MAE | 符号准确率 |
|---|---:|---:|
| Δmean | 1536.5 | 6/18 |
| Δmean + L1 | 1185.3 | 10/18 |
| **Δmean + Δtail** | **1108.5** | **15/18** |
| Δmean + L1 + Δtail | 1380.8 | 14/18 |
| Δmean + L1 + Δtail + Δworst | 1534.1 | 14/18 |
| Δtail | 1212.4 | 10/18 |

**MAE ≈ 1,100 分 vs 当前单步信号 1~123 分 → 定量预测不可用。**

根因是转换率本身跨 3 个数量级（本地 gain 单位 → 官方分）：

| 配对 | Δ本地 mean | Δ官方 | 隐含转换率 |
|---|---:|---:|---:|
| std → v160L | +0.633526 | +3586 | 5,660 /单位 |
| v160L → v166L | +0.003064 | +3 | 979 /单位 |
| v166L → v182L | +0.000020 | +1 | 50,000 /单位 |
| v138L → v140L | +0.002535 | +123 | 48,521 /单位 |
| v86L → v140L | +0.063198 | **−165** | **−2,611 /单位** |
| v160A → v168A | −0.000880 | **+60** | **−68,182 /单位** |

不存在任何稳定的单调单值映射。

### 2.2 决策规则 bake-off：符号/风险判读可行

`L1` = 本地逐 case gain 的**平均绝对变化**（改动幅度），不是 Δmean。

| 规则 | 提交且官方正 | 提交但官方负 | 正确拒绝官方负 | 漏掉官方正 | 精确率 |
|---|---:|---:|---:|---:|---:|
| R1 Δmean > 0 | 7 | 4 | 4 | 2 | 0.64 |
| **R2 Δmean > 0 且 L1 < 0.02** | **5** | **0** | **8** | 4 | **1.00** |
| R3 Δmean > 0 且 Δtail ≥ 0 | 7 | 3 | 5 | 2 | 0.70 |
| R4 Δmean>0 且 L1<0.02 且 Δtail≥0 | 5 | 0 | 8 | 4 | 1.00 |
| R5 Δtail > 0 | 7 | 3 | 5 | 2 | 0.70 |
| R6 Δmean>0 且 Δworst > −0.01 | 5 | 3 | 5 | 4 | 0.62 |
| R7 compact Δmean > 0（n=7） | 4 | 0 | 2 | 1 | 1.00 |
| R9 Δmean>0 且 paired_med ≥ 0 | 6 | 4 | 4 | 3 | 0.60 |
| R10 Δmean>0 且 L1<0.02 且 linf<0.1 | 2 | 0 | 8 | 7 | 1.00 |

R2 拦下的正是代价最高的三次失败：

| 配对 | Δ本地 mean | L1 | Δ官方 |
|---|---:|---:|---:|
| v86L → v155L | **+0.063817** | 0.0920 | **−1163** |
| v86L → v156L | **+0.063721** | 0.0919 | **−1164** |
| v86L → v140L | **+0.063198** | 0.0924 | **−165** |
| v86L → v138L | **+0.060662** | 0.0935 | **−288** |

**分段一致率**：微扰区间（L1 < 0.02）Δmean 符号一致 **7/9**；大改区间（L1 ≥ 0.02）**4/8**，
且 4 个不一致全部是"本地大正、官方大负"。

## 3. 唯一可靠的"拟合"：结构性可加模型

### 3.1 模型

官方分数在 Linear / Attention 两侧**可加**（v175 实测 interaction = 0）：

```
Ŝ(组合) = 1001 + C_L(Linear 算法) + C_A(Attention 算法)
```

其中 `1001 = S(v162)` 是双标准 codec 零点。已标定的 `C` 值：

| Linear 算法 | C_L | Attention 算法 | C_A |
|---|---:|---|---:|
| std | 0 | std | 0 |
| v160L（完整栈） | 3586 | v160A | 12944 |
| v166L（rank-1） | 3589 | v168A（A1） | 13004 |
| v182L（rank-2，推导） | 3590 | v171A（A4） | 12656 |
| v174L（Kron-CAT） | 3507 | v176A（C1） | 12963 |
| | | v180A（D1，推导） | 13007 |
| | | v183A（覆盖率，推导） | 13007 |

旧 cluster 只有**差分**可识别（缺少与 std 配对的提交）：
`C_L(v138L) − C_L(v86L) = −288`、`C_L(v140L) − C_L(v86L) = −165`、
`C_A(v158A) − C_A(v86A) = +117`、`C_A(v84A) − C_A(v86A) = −1227`、
`C_A(v138A) − C_A(v86A) = −1741`。绝对水平不可识别（差一个自由度）。

### 3.2 用这个模型分解 4167 分差距

当前 v182：`C_L + C_A = 16597`，`S = 17598`。榜首 21765 → 需要 `C_L + C_A = 20764`，缺口 **4167**。

> **2026-09-04 勘误**：本小节初版把"侧隔离提交总分 `S`"误当成侧贡献 `C` 代入比值
> （得 `14008/4590 = 3.05`）。`4590 = S(v166)`、`14005 = S(v168)` **含 1001 零点**，
> 不是 `C_L` / `C_A`。正确口径见下。`C` 值一律由 `C = S(侧隔离提交) − 1001` 读出。

当前 v182 = v182L + v180A：`C_L = 3590`、`C_A = 13007`，`C_L + C_A = 16597`，
`S = 1001 + 16597 = 17598` ✓。榜首 21765 → 需要 `C_L + C_A = 20764`，缺口 **4167**。

按当前侧比 `C_A / C_L = 13007 / 3590 = 3.62` 等比例分配（放大系数 `20764/16597 = 1.2509`）：

| 侧 | 当前 C | 目标 C | 缺口 | 相对提升 |
|---|---:|---:|---:|---:|
| Linear | 3590 | 4491 | **+901** | +25.1% |
| Attention | 13007 | 16273 | **+3266** | +25.1% |

`4491 + 16273 = 20764` ✓，`901 + 3266 = 4167` ✓。

再按本地"平均转换率"折算成**本地 gain 目标**（仅量级参考，非线性）：

- Linear：`3586 / 0.6335 ≈ 5,660` 分每单位 → 需本地 L 从 `0.6366` 提到 **≈ 0.796**
- Attention：`12944 / 0.7424 ≈ 17,436` 分每单位 → 需本地 A 从 `0.7418` 提到 **≈ 0.929**

> 与 v160 口径（`12944/3586 = 3.61`）一致：**"Attention 边际 ≈ Linear 的 3.6 倍"这个
> 结论仍然成立**，`AGENTS.md` / `current-solution-status.md` 中的 `1:3.61` 无需修改。
> 出错的是本文初版的 `3.05`。

> 这个折算**在顶端无效**：顶端实测边际转换率在 979 ~ 50,000 之间摆动，
> 因为官方增量已降到 1~3 分、被整数化噪声淹没。它只能说明一件事——
> **本地剩余 headroom（L 0.363 / A 0.258）在数量级上是够的，缺的是把本地 gain
> 变成官方 gain 的机制，不是 headroom。**

### 3.3 提交策略含义：侧隔离的信息效率高于组合

一次**侧隔离**提交（候选侧 + 对侧用 std）直接读出 `C_L` 或 `C_A` 的绝对值；
一次**组合**提交只给出 `ΔC_L + ΔC_A`。在可加性只有 v175 一个验证点的情况下，
继续做侧隔离可以同时积累可加性证据并获得可直接代入模型的绝对贡献。
v176 之后的 v180/v182/v183 都是组合版本，信息效率较低。

## 4. 官方时间的本地拟合（这一项是可做的）

21 个版本的回归（本地为 CUDA 六 API 分解计时，官方为鲲鹏机实测）：

| 模型 | R² | MAE |
|---|---:|---:|
| `T = a + b·本地API总时长` | 0.432 | 18.6 s |
| `T = a + b·W_calib + c·A_calib + d·dyn_qkv` | 0.511 | 15.7 s |
| **`T = a + b·W_calib + c·A_calib + d·dyn_act + e·dyn_qkv`** | **0.799** | **10.1 s** |

```
T_official ≈ 170.3 + 0.1154·W_calib + 0.6939·A_calib + 0.7344·dyn_act − 1.5837·dyn_qkv
```

**关键读数**：本地 Linear 校准 1 秒在官方只值 **0.115 秒**（GPU 大矩阵，鲲鹏相对便宜）；
本地 Attention 校准 1 秒在官方值 **0.694 秒**（小张量 + 控制流，鲲鹏相对昂贵 6 倍）。
这解释了 v161 timeout：动态 Q/K/V 精化本地只加 28 s，官方却耗尽 68 s 余量。

**使用方式**：预测值 + 20 s 余量（2×MAE）作为 300 s 硬限判据，即**预测 < 280 s 才提交**。
模型对最新版本系统性低估（v182 残差 +21 s、v183 残差 +19 s），余量不能省。

### ⚠️ 对 v184（未提交候选）的即时判定

| 项 | v183（已测） | v184（未提交） |
|---|---:|---:|
| 本地 Attention mean | 0.742340 | **0.748409**（Δ **+0.006069**） |
| 本地 Δmedian / Δp10 | — | +0.018074 / +0.003866 |
| L1 / linf | — | 0.01369 / 0.24134 |
| 本地 Attention 校准 | 68.2 s | **118.8 s**（+50.6 s） |
| 预测官方时间 | 283.8 s（实测 279.7） | **322.5 s** |

**v184 同时满足 R2（Δmean > 0、L1 = 0.0137 < 0.02）且是 v158 以来本地 Attention 最大提升，
但预测官方时间 322.5 s，即使按 20 s 保守修正仍 ≈ 315 s > 300 s，超时风险极高。**
若要用这个机制，必须先压缩 Attention 校准成本（目标 ≤ 85 s 本地，即预测 ≤ 300 s）。

## 5. 建议执行的本地判读协议（替代"拟合"）

对每个新候选，本地只产出下面 5 个读数，不做官方分预测：

```
① Δmean(default panel)     —— 方向与幅度（仅在 L1 门槛内采信）
② L1 = mean|Δgain|         —— 过拟合风险门槛，硬阈值 < 0.02
③ Δtail（最差 20% case）   —— 稳健性，要求 ≥ 0
④ 机制类型标签             —— 解析/结构等价  vs  校准统计拟合
⑤ 预测官方时间（§4 模型）  —— 硬阈值 < 280 s
```

判读表：

| 机制类型 | L1 | Δmean | Δtail | 预测时间 | 结论 |
|---|---|---|---|---|---|
| 解析 | < 0.02 | > 0 | ≥ 0 | < 280 s | **可提交**（历史 6/6 非负） |
| 解析 | < 0.02 | ≤ 0 | — | — | 不提交（v168A 是唯一反例，Δmean<0 却 +60） |
| 拟合 | 任意 | 任意 | — | — | **默认不提交**（1/5 正，最好 +19） |
| 任意 | ≥ 0.02 | > 0 | — | — | **不提交**（4 个大改全部官方负） |
| 任意 | 任意 | 任意 | 任意 | ≥ 280 s | **不提交**（超时无分） |

**明确不做的事**：
- 不用本地数值回归官方绝对分（MAE ≈ 1,100 分 ≫ 信号）；
- 不用 compact / GPT-2 / opt 单方面做否决（compact 样本仅 7 个且 ρ 高但置信区间宽；
  GPT-2 / opt 实测 ρ ≈ 0）；
- 不做参数邻域扫描（既有纪律，本分析未改变）。

## 6. 让本地真正"能拟合"的唯一路径：加 OOD 测试集

> **[2026-09-04 已实现]** OOD 测试集已落地：语料 `data/ood-suite-v1/`（code/news/zh 三域，
> 由 `workbench/build_ood_corpus.py` 确定性生成），评测器新增 `--ood` 模式（校准保持
> WikiText，15 个 OOD 测试窗口 → 168 Linear + 120 Attention，case 数与默认面板一致，
> NVFP4 缓存独立、不触碰 in-dist 缓存）。v182 基线：`gain_in − gain_ood` =
> Linear `+0.015903`（0.636609 → 0.620706）、Attention `+0.020590`（0.741829 → 0.721239）。
> 候选判读用**相对父版本的差值变化 `Δ(gain_in − gain_ood)`**，不用绝对差值。
> 数据：`artifacts/official_eval/ood.json`、`logs/official_eval/ood.md`；执行记录
> `logs/execution/2026-09-04-ood-suite-baseline-v182.md`。

所有本地失效的根源是同一条：**本地校准窗口与测试窗口同源于 WikiText-2**，
因此"拟合本地窗口统计"的解在本地永远看不出问题，只在官方隐藏数据上崩。

最小改动（不改算法，只改评测器）：

1. 在 `evaluator/official_eval.py` 的 panel 中增加一路 **OOD test 窗口**：
   校准仍用 WikiText-2 train，test 用**不同语料**（PTB / C4 子集 / 代码 / 中文），
   本地 `data/` 目前只有 `wikitext-2-raw-v1`，需新增一份离线语料；
2. 报告 `gain_in`（WikiText 同源）与 `gain_ood` **两个均值**，并把
   **`gain_in − gain_ood` 作为过拟合指标**——这条差值在 v140/v155/v156 上应当显著为正，
   可以用来复核本文的 L1 门槛是否抓住了同一现象；
3. 把 OOD 结果作为**选择裁判**（选哪个变体、是否晋级），同源结果只作回归检测。

预期收益：如果 OOD 差值能复现 v140/v155/v156 的失败，那么本地就能在**不消耗提交配额**
的前提下筛掉"拟合型"机制，把仅剩的 6 次配额全部用于解析型机制。

**成本**：需要一份离线 OOD 语料 + 一次评测器改动 + 重跑 v158/v160/v168/v171/v176 五个
版本做标定（约 5×5 分钟 GPU），不消耗官方配额。
