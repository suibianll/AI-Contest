# 当前评估系统合理性审计与清理

结论：保留 eval-v3 的最终输出误差、共享校准、独立 holdout、父子配对及合法状态检查。
本次主要错误是代码和执行文档仍保留已退役政策；4B 结构代理不能预测官方分数或运行时间。

## 已修正

1. 日常 CLI 默认缓存从 0.5B 改为 4B；没有4B缓存即报错。当前没有4B OOD capture，日常 --ood 明确拒绝。
2. 分析器移除六API时间公式、280s拒绝和缺少fresh timing时的挂起；时间仅记录。
   为旧消费者保留预测字段为null。拟合机制标签仅提示独立验证，不作为失败结论。
3. README精简为当前入口；AGENTS、活动总计划、双侧当前工作包、proxy-v3说明和4B指引同步。
   修复4B指引的活动计划链接，以及“单侧冒烟六API全跑”的矛盾。
4. 旧过期清单增加09-07优先指针；计划历史区和状态/版本索引明确证据属性。
   旧时间拦截不是官方失败，不自动重开旧候选。

## 合理性与使用边界

- 4B prepare_shard按attention_layers过滤DeltaNet，并按test_qkv_windows覆盖Attention窗口，
  当前全量是336 Linear/72 Attention。不能套用旧48或120例口径。
- 本地 gain 是相同标准参考下最终输出误差改善，适合固定父子的机制诊断；不是官方准确率。
- 总L1分析器保留通用规则，持续优化工作包应显式另算负向损失与split门，不把通用reject当专项裁决。
- 结果复用当前检查源码路径/SHA、缓存路径、场景和分片；未完整验证同路径缓存内容、
  evaluator版本和设备。复用前仍须人工核对这些manifest身份；本次未改结果格式或缓存协议。
- 官方是否晋级仍需同源码SHA的官方分数和时间；分析器eligible不是全套提交审批完成。
