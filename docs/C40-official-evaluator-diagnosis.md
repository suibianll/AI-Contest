# C40 官方结果与本地评测器诊断

日期：2026-08-28

## 结论

本地评测系统已经不能可靠排序当前合规候选，必须停止使用现有 GPT-2-small Linear
mean 和“六项矩阵全正”作为晋级条件。现有证据不支持官方评测跑错文件；C40 更可能是
对高度重叠的本地数据和单一模型形状产生了代理过拟合。

C40 官方结果为 `14432 / 216.667s`，相对 C39-FW 的 `14613 / 159.2s`：

- 精度下降 `181` 分；
- 时间增加 `57.467s`。

官方新增时间与本地 CUDA algorithm-stage 新增时间
`45.32 - 27.54 = 17.78s` 的比例为 `3.23×`，与提交前约 `212.5s` 的保守总时间
预测接近。这说明正确候选及其新增求解路径被执行，问题集中在精度代理。

## 1. 本地与官方排序已经失去相关性

| 合规候选 | 本地 Linear | 官方分数 | 官方时间 |
|---|---:|---:|---:|
| C21-C | 0.5311 | 14437 | 166.6s |
| C38 | 0.5695 | 14092 | 170.57s |
| C39-FW | 0.5357 | 14613 | 159.2s |
| C40 | 0.5393 | 14432 | 216.667s |

四点 Pearson 相关系数为 `-0.902`。即使排除机制混杂较多的 C38，只保留
C21-C/C39/C40，相关系数也只有 `0.046`。因此旧校准报告中的线性兑换率不再有效。

以 C39 为基准：

| 候选 | 本地 Linear 变化 | 官方分数变化 |
|---|---:|---:|
| C21-C | -0.46pp | -176 |
| C38 | +3.38pp | -521 |
| C40 | +0.36pp | -181 |

C40 的本地正增益不仅没有兑换，官方方向还完全反转。

## 2. dev 数据存在 calibration/test 重叠

`real_data_eval.TEXT` 经 GPT-2 tokenizer 后只有 `409` token。默认配置需要：

```text
(2 calibration + 2 test) × 128 = 512 token
```

`collect_real_data` 在 token 不足时直接循环重复文本。因此默认 test 的 256 个位置中，
有 103 个位置已出现在 calibration，文本位置重叠约 `40.2%`。

offset 0/97/193/389 只是同一 409-token 环的旋转，不是四个独立语料；amax4 和 pow2
也只改变同一激活的 NVFP4 编码。因此此前记录的六项矩阵本质上是一个窄分布的重复观测，
不能证明跨文档或跨模型泛化。

## 3. frozen holdout 也不独立

`HOLDOUT_TEXT` 只有 `257` token，而冻结配置需要：

```text
(2 calibration + 4 test) × 128 = 768 token
```

文本被重复三次。calibration 覆盖 256 个唯一位置，test 覆盖 257 个唯一位置，二者
重叠 256 个，即 `99.6%`。该 holdout 虽然与 dev 文本不同，但其内部 calibration 与
test 几乎完全复用同一文本，不能检测 C40 这类 calibration-Hessian 过拟合。

在修复前不要消耗剩余 holdout ledger 预算，也不要把已有 holdout 分数用于晋级。

## 4. 单模型和聚合口径不足

主要 dev 评测只覆盖 GPT-2 small 的 12 层与 `768/3072` FFN 形状。C40 在仓库已有
GPT-2 medium 全 24 层上的配对结果为：

| 版本 | Linear mean | fc | proj |
|---|---:|---:|---:|
| C39-FW | 0.4884 | 0.4417 | 0.4240 |
| C40 | 0.4902 | 0.4497 | 0.4267 |
| 变化 | +0.18pp | +0.80pp | +0.27pp |

跨模型增益只有 small 默认场景的一半左右；前四层中 `proj` 还从 `0.5091` 降到
`0.5031`（`-0.60pp`）。跨块非对角 Hessian 的收益随层和形状变化明显。

此外当前报告按“每层相对改善 → 每组件平均 → 六组件简单平均”聚合。官方是否按组件、
张量大小、原始 MSE 或场景权重聚合未知，单一 macro mean 无法校准隐藏评测。

## 5. 对 C40 的算法判断

C39 的独立 64×64 FULL64 只依赖块内 Hessian，官方曾给出 `+176` 分；C40 新增的
相邻块非对角项对校准分布更敏感。两个所谓独立 fold 实际来自同一重复文本，不能约束
跨文档 Hessian 符号和强度漂移。因而 C40 可能降低本地 `EHEᵀ`，却在官方激活分布上
改变错误抵消关系并失分。

这不是继续调 `ROBUST_MAX_MIX`、accept epsilon 或 pair coverage 能可靠解决的问题。
在新评测器建立前，所有这类调参都会继续拟合错误代理。

## 6. 下一步验证顺序

1. 官方端重新提交逐字节一致的 C39-FW 归档源码。若结果仍接近
   `14613 / 159.2s`，可确认官方稳定、C40 失败真实；若同一哈希显著下降，才有证据
   怀疑官方数据或计时环境漂移。
2. 修复本地数据集：calibration 与 test 使用不同文档，禁止 token 循环重复；每个
   split 的原始 token 数必须大于配置需求。
3. 将 GPT-2 small 与 GPT-2 medium 全层同时纳入开发矩阵，并增加不同序列长度与
   FFN 形状；不再把 token offset 当成独立数据。
4. 同时报告 macro relative score、按输出元素加权的 global MSE gain、最差层和
   layer-CVaR；候选必须在多模型上方向一致。
5. 用新的合规官方锚点重新估计排序模型。至少获得三次单机制、同一官方环境的结果前，
   不拟合官方绝对分数兑换率。

当前算法父版本保持 C39-FW。C40 只保留为“跨块 Hessian 在旧本地代理上正向、官方
负向”的失败证据。
