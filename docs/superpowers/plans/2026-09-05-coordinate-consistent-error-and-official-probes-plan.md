## 2. 本计划纠正什么

### 2.1 配对坐标与量化误差必须分开

根代码的动态 Q/K 包含 multiplier、permutation、rotation、block smoothing、pair transform；
Linear 同样含配对缩放、排列、旋转与残差变换。兼容后端 `official_eval.py` 目前以 player Q
搭配原坐标 standard K 构造 Q-only，W-only/A-only 也直接混合两条路径。

这类结果衡量的是“整条路径只替换一边”，混入了坐标失配，不能用来判断某个操作数的纯量化
损失。问题在分解解释，不意味着完整 player 输出评分错误；不改旧分数、旧 JSON 或兼容后端。

### 2.2 贡献不是隐藏权重

长度桶的官方差分一般形如 `C_j = sum_{i in bucket j} weight_i * mechanism_effect_i`。
`C_j / sum(C_j)` 只是该机制的有符号贡献比例；即使重构残差为零，也不能分别恢复
`weight_i` 与 `mechanism_effect_i`。两个锚机制比例相近只加强贡献模式可迁移的证据。
零收益加时间相近也不能证明隐藏桶为空：还可能是无效机制、正负抵消或调用时间变化。

### 2.3 经验小变化带不是已测得的随机噪声

沿用 `|step_gain| <= 4` 作为“小效应、低投入优先级”标签；官方稳定性按用户确认处理。
不同算法之间的 ±1～4 分差不能证明重复评测噪声，不提交同 SHA/逐位等价版本验证噪声。
多项分数的重构残差不能机械套用单次 ±4 的统计置信解释。

### 2.4 计时有协议边界

现有时间模型来自兼容 default panel。eval-v3 六 shard、OOD、诊断额外矩阵乘和命中校准缓存
的耗时不能直接代入；缺失 API 时间不得当成零。本计划将分片精度检查与提交前计时分开。

## 5. P1：实现同坐标系误差分解

### 5.1 最小实现范围

保持 `evaluator/official_eval.py`、`reference_hif4.py` 和根 `solution.py` 不变。
在 `evaluator/coordinate_diagnostics.py` 新增离线诊断逻辑，必要时在 `eval_system.py` /
`proxy_v3_eval.py` 增加显式诊断入口；默认评分和调用图保持原样。

优先复用既有 state/cache，按真实链重建编码前浮点张量。若必须截获内部张量，只在独立诊断
进程中使用受控适配，禁写入候选 state、禁注入正式提交模块。诊断额外前向单独计时。
未支持的变换明确报 `UNSUPPORTED_DIAGNOSTIC`，不得静默跳过并输出误差归因。

### 5.2 Attention：固定变换后做 2³ 浮点/量化替换

定义：原始 NVFP4 解码输入为 Q/K/V；按父 state 的完整链得到浮点 `Q_t/K_t/V_t`；父编码再
经官方解码得到 `Q_h/K_h/V_h`。所有组合使用同样的 GQA、缩放和有效 mask。

| 臂 | Q | K | V | 含义 |
|---|---|---|---|---|
| 000 | Q_t | K_t | V_t | 完整 state 的连续输出 O_t |
| 100 / 010 / 001 | 仅对应操作数用 h，其余用 t | 同左 | 同左 | 固定坐标下的单侧量化影响 |
| 110 / 101 / 011 | 对应两个操作数用 h，其余用 t | 同左 | 同左 | 固定坐标下的二阶影响 |
| 111 | Q_h | K_h | V_h | 实际部署输出 O_h |

每个臂同时保存 `MSE(O_arm,O_ref)` 和 `MSE(O_arm,O_t)`，不得把 reference 偷换后仍叫主分数。
对八个误差标量做包含-排除分解可以精确描述该固定 state 的交互；这种恒等式本身不是独立的
可加性验证，也不是全局算法上界。替换某一量化操作数后误差可能变大，负贡献原样保留。

另输出连续偏差 `B=O_t-O_ref`、量化扰动 `E=O_h-O_t`：

```text
MSE(O_h,O_ref) = mean(B²) + mean(E²) + 2*mean(B*E)
```

配对等价变换单独检查保持 attention 概率/输出；A1 logits gain 等主动改变连续输出的项
归入 B，不能误报变换实现错误。K-center 允许 logits 行常数平移。

logits 诊断仅在每行有效 key 上移除行均值后比较，不能处理 masked -inf 后再求均值；最终
输出 MSE 为主，probability MSE/KL 为辅，原始 logits MSE 只记录且标注平移敏感。

### 5.3 Linear：最终部署坐标的四臂及交叉项

重建最终浮点 `X_t/W_t`，实际解码为 `X_h/W_h`。四臂为 `X_t W_t^T`、`X_h W_t^T`、
`X_t W_h^T`、`X_h W_h^T`；都对原始 `XW^T` 计输出误差。验证连续域乘积守恒。

令 `E_X=X_h-X_t`、`E_W=W_h-W_t`，保存三项矩阵及其均方与交叉内积：

```text
X_h W_h^T - X_t W_t^T = E_X W_t^T + X_t E_W^T + E_X E_W^T
```

不能把三个非负 MSE 相加当总误差；正负交叉项说明误差抵消或放大。按 layer/role/shape/
split 输出，control 与主评分仍按原协议匹配。

### 5.4 正确性与覆盖

先用小型确定性 FP64 合成数据验证：非平凡配对缩放/旋转、K-center 行平移、GQA、causal mask、
Linear 残差变换，以及“只混一边原坐标会失配”的反例。针对性测试放在
`tests/test_coordinate_diagnostics.py`，不以实现自身输出作为唯一期望值。

- 小型代数测试采用相对范数残差 `<=1e-10`；FP32 实际链初始容差为 `<=1e-4`，同时报告绝对
  和相对误差。超限先用小样本 FP64 定位，不通过放宽容差掩盖缺失变换。
- 111 / Linear 双量化臂复用父已解码张量，必须复现同 case 主输出；新增诊断开关不得改变
  six-API 结果、state、case keys、标准误差和 reference energy。
- 先完成目标侧 shard 0 的接口检查，再覆盖六 shard；既有输出可重放的部分零 API 重放。
- 旧的混坐标分解保留原名并标为 `path-replacement`；新增 `coordinate-consistent-v1` 字段，
  不覆盖旧日志、不将两种分解混排。

产物：`artifacts/proxy_v3/coordinate-diagnostics-v186/<run-id>/` 下 manifest、逐 case JSON、
报告；`logs/execution/<date>-coordinate-diagnostics-v186.md` 记录测试与归因。

## 6. P2：固定小面板的格式误差定位

### 6.1 面板与信息隔离

本阶段只诊断，不在 holdout 上学习可部署规则。保留已关闭窗口/变换家族的结论，不重跑旧搜索。
固定选深度 `0, floor(L/3), floor(2L/3), L-1`（24 层时 0/8/16/23）：

- Attention 取兼容 default 原有五个长度/窗口位置，共 20 case，保留两个 1024 的不同身份；
- Linear 取七 role 与 validation/test 两个窗口，共 56 case；
- 每个 case/操作数最多取 64 个沿展平块索引均匀分布的块；不足则全取，不按最大误差挑块。

所有选择在读取误差结果前写入 manifest。此面板单独命名 `format-diagnostic-v1`，不冒充
compact 或六 shard；P1 的完整结果用来检验诊断是否只反映少数 case。

### 6.2 放宽臂与解释边界

固定父 state、其余字段和操作数，每次只干预一种约束。重用 P1 浮点替换结果作为参照。

| 诊断 | 固定内容 / 操作 | 可以支持的结论 | 不能支持的结论 |
|---|---|---|---|
| R0 浮点替换 | 单操作数用同坐标浮点值 | 完全移除该侧量化的输出效应 | 可部署收益上界；它可能破坏原误差抵消 |
| R1 mant 连续化 | 固定 sign/scale/lv2/lv3，mant 投影至连续 [0,7/4]，保持原覆盖范围 | 舍入网格与饱和剩余的差异 | 调大合法码搜索窗口就能获得同样改善 |
| R2 基础 scale 连续化 | 固定码字/层级，单块非负最小二乘拟合编码前张量的 scale | 基础 scale 离散误差的诊断线索 | operand 最优等于输出最优，或 HiF4 能表示该解 |
| R3 层级因子连续化 | 固定其他字段，分别对 lv2 或 lv3 作一次独立的 [1,2] 最小二乘投影；两臂不串联 | 层级离散约束与当前码字的关联 | 当前合法层级求解器有 bug 或未收敛 |

以基础 scale 为例，固定块解码形状 b、浮点目标 z，非零 b 上
`s*=max(0,<b,z>/<b,b>)`；零块记不可识别，不构造无依据的 scale。
R2/R3 只是固定其他字段的条件解；不交替优化、不扫描邻域，也不声称是全局最优。
每个放宽臂都重新计算实际输出误差，并同时报告 operand MSE，检查二者是否反向。

放宽格式的输出强制标记 `diagnostic_only=true, legal_candidate=false`；只在诊断数学中使用，
不得导出到 `solutions/` 或官方队列。R1～R3 之间存在重叠，不把改善相加当可恢复余量。

### 6.3 选择机制的证据要求

报告每臂的 median、负 case、worst-quartile、validation/test 同号率、跨深度分布与交叉项。
预注册的研究优先级筛选为：输出误差的 paired median 下降、至少 3/4 深度组均值下降，且
不少于 3/4 可配对 validation/test 单元同为正；这些是本轮研究筛选条件，不是官方预测规律。

未满足时记 `INCONCLUSIVE`，不据此宣布整个算法空间饱和。满足时仍须写出该误差如何在合法
五字段、有限 state 与分离动态 API 中被利用；如果没有实现路径，只登记诊断发现。
本阶段至多选一个主机制进入 P4，不为满足条件改面板、投影次数或结果阈值。

| W2 | rows > 256 且 rows/cols > 1.33 |
| W3 | 其余 |

本地证明全集覆盖、无重叠；固定形状只作为观测分桶，不宣称等于隐藏模型 role。
非目标桶与 v162 逐位一致，四桶全开与 v163 逐位一致。
`C_j=S_Wj-1001`，`R=3586-sum(C_j)`。本地 case 数、元素数和能量只作描述性对照，不拟合
官方权重或据此恢复隐藏模型。未启用桶不能执行 player calibration 后再伪称 standard 时间。

### 7.5 第二长度锚与残差处理

默认核心矩阵共 10 个新探针（2+4+4），不是额度；不自动执行旧计划的 14 个混合探针。
若 P4 的方向选择需要判断长度贡献能否跨机制迁移，可执行一次固定的第二锚，最多 4 个新探针。
触发理由须在看到第二锚桶结果前写入日志；不以第一锚 R≈0 为充分或必要条件。

第二锚沿用 v171 A4 的原始 Q/K/V 整体变化，全关 v164，全开 v171，锚差为
`13657-13945=-288`，不是相对 v168 的 -348。必须先满足 P3-B 的共同键和逐位端点检查。
此处只作预注册诊断，不重启已关闭 A4 优化家族；比例一致也不称已识别样本权重。

任何重构残差先核查 endpoint SHA、cohort、分桶互斥、状态选择和官方回传，不立即称为噪声。
报告绝对值与相对总效应；`|R|>max(20,0.01*|总效应|)` 作为本轮停止简单贡献解释的工程阈值，
不是统计检验。小于阈值也只表示未观察到实质冲突。没有直接 reachability 遥测时保留不可识别性。

## 8. P4：仅在诊断支持后注册一个新机制

### 8.1 注册卡必须先于候选 holdout 评测

| 必填项 | 具体要求 |
|---|---|
| 病因证据 | 指向 P1/P2 的具体 case 分布、输出误差与官方贡献结果；不只有 aggregate mean |
| 新颖性 | 列出与已关闭家族的实质差别；换名字、增 rank/邻域/coverage 不算新机制 |
| 数学机制 | 保持什么连续量、优化什么部署输出、为何合法字段能够承载 |
| 父版本 | 低成本从 v186 的目标侧构造，复杂机制从 v180 的目标侧构造；非目标侧冻结 v162 STD |
| calibration/online 划分 | 校准学习；在线仅固定规则，说明 API 能看见哪些张量，禁止假设 Q API 能访问实时 K |
| 唯一配置 | 固定候选数、正则、迭代上限和接受规则，官方失败后不扫邻域 |
| 复杂度 | 校准/动态分开列；最终时间必须用兼容协议实测判断 |
| 失败条件 | 无 reachability、非法 state、泛化失败、时间不安全、官方非正分别如何结束 |

先复用 v163/v166/v168 等已确认单侧端点；若所选 v186/v180 精确目标侧尚无独立官方结果，
必须先登记一个必要的父侧端点测量，不能把组合分数减出“官方实测父分”。这不是重复等价提交。
两侧独立归因纪律继续有效；本轮只开发一个侧的新机制。

### 8.2 条件方向，不预先宣称算法有效

- P1 显示 Q/K 舍入交叉项是主要问题：只研究可由 calibration 编译、分离动态 API 可独立
  执行的配对编码规则；不能退回已关闭的实时 Gram 搜索或 importance 移植。
- P2 显示合法层级结构存在未利用的解析关系：先证明与现役 exact hierarchy/GPTQ 求解器
  不等价，再设计固定复杂度规则；仅“连续解好很多”不足以注册。
- P1 显示主动 gain 与量化误差的抵消主导：先记录该依赖及跨 holdout 稳定性，不直接重开
  gain/clamp/threshold 调参。
- 若所有发现均落在已关闭家族、非法自由度或不可编译规则，P4 记 `NO_SUPPORTED_MECHANISM`，
  结束本轮并报告缺失的证据；不为产出版本强行重写方案。

### 8.3 候选本地验收

1. 目标侧最小接口 smoke：六 API 可导入、状态合法、有限输出、control 不变。
2. 目标侧 eval-v3 六 shard，按 `(layer,role,test_window,split,length)` 严格父子配对；记录
   mean/median、L1、worst-quartile、负 case、validation/test 同号率及 P1 分解。
3. 沿用风险门禁 `Δmean>0 且 L1<0.02`；注明这是历史经验筛选，不保证官方非负，也可能遗漏
   大改机制。失败即不提交优化候选，不利用无限提交绕过此门禁。
4. 同 SHA、同 calibration 身份的 ID/OOD 配对，`|Δ(gain_in-gain_ood)|>0.01` 禁止提交。
   两域若改变 calibration folds/state，先修复比较条件，不把校准变化误认为 OOD 泛化。
   已有旧默认面板阈值在 v3 上只按现行规则保守使用，不重新宣称已统计标定。
5. focus 尾部和收益集中度必须解释；未修改侧必须逐位一致。cross-model 仅作描述性记录，
   不反向选配置、不作为晋级或否决证据；优先复用已有记录。
6. 完成下一节的正式计时与单文件脱离仓库导入；通过后才形成可提交包。

## 9. 提交前时间门禁与官方裁决

### 9.1 计时协议

每个准备提交的不同算法 SHA 做一次兼容 default panel 的新鲜六 API 计时，使用只读 dense/
NVFP4 输入缓存，禁用候选 calibration artifact 复用和额外诊断。兼容后端只承担本计划明确
需要的低频计时审计；参数以现有 parser 为准，不能给 `eval.py` 编造不存在的 default 开关。

完整探针与组合候选须覆盖其真实六 API；目标侧优化也不能用另一侧缺失值=0 填公式。
若可复用同 SHA/同协议的新鲜计时则不重跑。父版本的既有计时直接复用。

```text
T_pred = 170.3 + 0.115*W_calib + 0.694*A_calib
                  + 0.734*dyn_act - 1.58*(dyn_q+dyn_k+dyn_v)
提交条件：T_pred < 280s；最终官方必须 <300s。
```

`dyn_qkv` 负系数是共线性现象，不能靠增加无用计算降低预测。遇到明显超出训练样本复杂度的
新机制，预测值仅作必要条件；不将它当超时保证。预测不安全就停止该候选，不提交纯计时 A/B。

探针附带时间可用于检验旧模型。先检查设计矩阵秩/共线性与协议，再比较原模型和非负回归；
移除原计划对“六 API 独立斜率必可识别”的承诺。按探针家族整体留出验证；只有至少三个可用
家族、各折稳定且 MAE 优于原模型的同批验证结果，才提出模型更新。否则保留旧模型。

### 9.2 官方结果与晋级

| 结果 | 操作 |
|---|---|
| 未收到官方结果 | `official_score/time=NA`，等待回传，不以本地值代填 |
| 官方接口/合法性失败 | ERROR；修接口不改算法假设，保留失败记录 |
| 官方 >=300s 或明确 timeout | TIMEOUT；保留机制证据，不沿已关闭动态族缩参数重试 |
| 探针正常完成 | PROBE_COMPLETE，正负均保存，不自动替换根 |
| 优化候选相对精确单侧父 <=0 分 | REJECTED，关闭该预注册机制配置及邻域 |
| 优化候选相对精确单侧父 >0 且时间通过 | 单侧 RETAINED；可构造一次与已确认另一侧的组合 |
| 组合超过 17599 且时间通过 | 才可成为新完整父，根切换到官方计分 SHA |
| 组合未超分但显著更快 | 记录 Pareto/预算父价值，不称为最高分父 |

step_gain 为 +1～4 的候选按现行正增益规则登记，但研究优先级记“小效应”，不宣称突破或
因此开启参数扫描。每次组合都实测 interaction；不把过去侧向可加当永久定律。

## 11. 工作量、停止条件与最终交付

以下是实施工作量估计，非官方回传日程；GPU/接口异常需单独记录，不靠重复运行消耗时间。

| 里程碑 | 预估实施工作量 | 本地/官方工作边界 |
|---|---|---|
| M0：P0 | 约 0.5 个工作日 | 只读审计与缺失项清单 |
| M1：P1 | 约 1～2 个工作日 | 新诊断实现、针对性测试、父侧必要捕获 |
| M2：P2 | 约 0.5～1 个工作日 | 固定面板一次放宽诊断，无官方提交 |
| M3：P3 | 约 1～2 个工作日准备，回传耗时另计 | 三块共 10 个预定探针，条件第二锚另计 |
| M4：P4/P5 | 机制卡通过后再估算 | 最多一个主机制；必要父侧端点、候选与一次组合 |

这些是工作量范围，不要求先做满全部实验才报告发现。每个里程碑交一份可审查报告：事实、
未知项、下一步是否满足条件。出现以下情况立即结束当前分支：

- 同坐标重建未通过复现/代数检查：只修诊断，不进行算法归因；
- 长度 API 没有共同场景键：停止长度切换探针，其他独立块可继续；
- 格式放宽只有非法自由度有收益、或新假设仍是关闭家族：不注册优化候选；
- 官方贡献与本地重点不同：保留差异，优先跟进官方有证据的机制，不改本地评分权重；
- 候选触发风险/时间门禁或官方负向：按预注册条件关闭，不围绕结果调参数。

最终交付应回答：①纯量化与连续偏差各占何种作用；②哪些字段约束与输出误差相关；
③哪些机制在官方哪些桶产生了收益；④哪个合法新机制获得/未获得官方支持；⑤完整父版本
是否改变、计分 SHA 和时间是什么。即使未涨分，也要明确排除了什么、仍不知道什么，不能
把“没有新证据”写成“所有方法已穷尽”。
