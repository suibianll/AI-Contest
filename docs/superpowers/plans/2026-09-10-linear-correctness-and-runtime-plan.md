## 1. 目标与统一决策

保住已确认的375分收益，修正局部候选代价，然后减少重复计算，为后续精度改进留出运行空间。官方硬限300s；不预测释放多少官方秒数。

每卡从启动时最高分完整根构建，登记父SHA与一个固定配置；保留六API。不得拿待官方v231当父、不得机械拼接Attention归档。若官方期间换根，旧候选保留原父，新构建才使用新根。版本号归档时统一登记并检查冲突，不预占v232等编号。

已有待回传项：v231 Linear K=2；v230 Attention A-FIX1已回传TIMEOUT(>300s)、REJECTED（见`logs/execution/2026-09-10-v230-attention-afix1-official-timeout.md`）。仅登记一次官方结果，不重交同SHA。两者开发已结束，不作为并行活动卡。v231正向才按官方完整结果晋级，否则保留v230；不再扫描K。

## 2. L-QF1：修正局部二次代价（首卡）

假设：当前候选排序使用了错误的局部二次代价，正确二次型能减少误提议与漏选；是否最终增益必须实测。

- 入口：`_em1_dynamic_descent` 的 `quadratic` 计算；当前式 `krba,bij,krbj->krb`。
- 唯一改动：改为 `krbi,bij,krbj->krb`，实现 `delta^T local_gram delta`。暂不改成特化对角公式、不换计算库、不改其他路径。
- 固定：继承父K（当前1）、8个pm1候选、16组调度、覆盖范围、scale/hierarchy/sign语义及整行联合接受全部不动。
- 工作目录：`workbench/full_solution/linear-qf1-quadratic-cost/`，完整候选自包含；根和既有归档只读。
- 最小验证：非对角SPD矩阵与单坐标/一般delta的显式二次型对照；验证线性项+二次项与直接目标差一致；包含旧式不等于真值的反例。用独立参考式，不写自我重复测试。
- 验证六API独立导入、合法state、finite、Attention/Weight控制、真实提议及最终接受计数、硬码变化；关闭修正时复现父。
- 运行目标侧shard0后六shard一次，记录真实输出差与288/0/48旧证据的同口径对比；不以本地均值正负作官方提交门。
- 若最终完全恢复父/逐位相同，NO_EFFECT，不分配正式版本；若合法可达且非等价，归档单一代表交官方。
- 官方下降/超时只关闭此修正代表，不反复改候选数/阈值/组粒度。官方晋级前，v230原计分源码不改。

## 3. L-TF1：复用首遍梯度（第二卡）

从届时最高分完整根构建；若QF1待回传则仍以已确认根为父，不把未定价修正混入本卡。

- 唯一机制：复用进入pass循环前已计算并检查过的梯度，首pass不重复计算。K>1时保留之后每pass的重算顺序。
- 当前代码前置与首pass均计算 `(deployed-reference)@metric + reference@h_matrix`；中间仅构造索引/候选常量并clone deployed，未改变值。先静态确认此前提再改。
- 不同时修改求逆、矩阵精度、局部代价或共享助手。保留非有限检查与失败路径行为。
- 工作目录：`workbench/full_solution/linear-tf1-gradient-reuse/`。
- 最小控制：正常与非有限路径对照；父子五字段及输出对照；确认少执行一次梯度表达式。计时使用相同state/device和独立无profiler配对，记录中位/离散程度，不换算官方秒数。
- shard0和目标侧六shard各按指引复用/执行一次。若声称纯时间变化，必须证明硬码与输出等价；若出现硬码差异先查原因，不用`|Δ|≤0.002`一类容差声称等价。
- 这是实质计算量变化的单次成本验证，允许输出等价但执行不同的候选官方计时；不重复相同执行路径估计噪声。官方同分且更快可作为完整工作父（v202同类），官方分数下降或超时则不晋级。

## 4. 从定位到一张固定卡

定位问题（"父激活GPTQ、新增下降、度量求逆/拷贝各自占多少无profiler调用时间？"）
已由 v233 开发过程中取得的证据回答，见
[`logs/execution/2026-09-10-linear-tf1-gradient-reuse.md`](../../../logs/execution/2026-09-10-linear-tf1-gradient-reuse.md) §5.4。
方法为"整调用 + 单部件打桩"归因（`workbench/full_solution/linear-tf1-gradient-reuse/attribute.py`），
事件时钟与独立 `perf_counter` 一致到 2% 以内。

**实测分母（layer0/q，无 profiler，CUDA event）：**

| | 128 行 | 512 行 |
|---|---:|---:|
| 父根动态激活路径（含 hook 开销） | **90.0%** | **93.2%** |
| 新增下降（L-EM2 的整段） | 10.00% | 6.79% |
| 度量构造/求逆/拷贝 | 3.24% | 3.48% |
| 下降内**全部**矩阵乘合计 | 2.24% | 2.81% |

**读数：主项是父根自己的动态激活路径，不是本计划前两卡编辑的那段下降。** 下降只占 7–10%，
度量占 3.2–3.5%，两者加起来仍远小于其余部分。因此 §4 按分支 2 收敛为一张卡，
且**只选一项**；不同时实现三条。

### 4.1 固定卡：父激活路径内的单次拆分，再实现块间补偿预计算

**这一步不许跳过。** 上表的 90–93% 是"关掉 `em1` 载荷后的整段"，它同时包含 nvfp4 编码/舍入、
GPTQ 的逐块 solve、以及 hook 与 state 拷贝。分支 2 的前提是"逐块 solve 为主"，
而本计划**尚未证明**这一点——把 90% 直接当成 solve 就是拿猜测当定位。
所以第一步只开**一个**探针、只回答一个问题：在这 90–93% 里，编码/舍入路径、逐块 solve、
hook+state 开销各占多少？一次拆分，不做参数/seed/阈值/粒度扫描，不加第二个探针。

**若（且仅若）逐块 solve 为主，机制固定为：** 预计算原始块间的补偿系数，
动态阶段只按当前输入产生的块序取用，保留顺序补偿的语义不变。
独立验证浮点重结合与异常/非有限路径；六 API 与 Attention 半边不动。

**门与判据：**

- 官方硬限 300 s 是唯一时间门，父根已用 292 s。本卡的目的是夺回**秒级**空间，
  不是再省千分之一，因此以"官方秒数可分辨地下降"为唯一接受条件。
- 精度侧按本轮统一规则：六 shard 与父根同口径，出现回退逐条记录；本地 Δ 只作诊断。
- 若拆分结果显示主项是编码/舍入路径或 hook 开销，则本卡改写为对应分支（分支 3 或
  直接说明该路径不可在不动编码目标的前提下压缩），不再另开第二份活动总计划。
- 不以猜测计时开大量探针；不把整 API 事件数归因于单个 einsum，不把 view 操作当 GPU kernel。

本节到此替换完成，不再保留"待定位"状态。
