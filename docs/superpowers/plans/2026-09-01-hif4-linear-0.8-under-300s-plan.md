### 2.2 v138 为什么失败

v138 不是“原样 v86 Attention”。它把 v86 的 4096-token 统计、4/8/16 block-Hadamard、
真实 Attention 输出终选器和 scale-aware K-centering，改成了 256-token 统计、0/16 候选、
单 seed，并关闭动态 Gram refine。结果是：

- v138 Linear 相比 v86 本地增加 `+0.100651`；
- v138 Attention 相比 v86 本地下降 `-0.003754`；
- 本地 API 节省 `111.37s`（`-37.2%`）；
- 官方只节省 `14.7s`（`-6.6%`），却损失 `1029` 分。

v84 到 v86 的 Attention 只增加 `0.001589`，官方就增加 `227` 分。v138 丢失的 Attention
增量是它的 `2.36` 倍，不能被称为“接近”。如果仅用本地 Linear/Attention 均值和正线性权重
解释 v86/v138 的官方反转，Attention 均值权重必须超过 Linear 约 `26.8` 倍；这说明新版
Linear 权重很低、隐藏数据泛化错位，或两者同时存在。

### 2.3 v139–v145 为什么没有意义

- v139 相对 v138 Linear `-0.00004125`，官方只多 1 分，属于近似持平；
- v140 相对 v138 Linear `+0.00003513`，小于当前固定面板能够支持的官方判断尺度；
- v141–v143 大幅回退；v144/v145 仍分别低于 v140 `0.000937/0.001099`。

这些实验只证明局部连续 gain、pair transform 和非对称选列 BDLR 不能解决问题。它们不构成
通往 `0.8` 的增长链，v140 不再作为算法最优点。后续停止 alpha、阻尼、sweep、block 数、
角度和候选数量的连续小修。

### 2.4 之前分析和执行的具体错误

1. 同时替换 Attention 和 Linear，破坏了官方分数的单变量归因。
2. 把“复杂度接近 v86”错误写成“v86 级 Attention”，没有原样冻结官方有效机制。
3. 反复在同一组 250/200 固定 case 上选择版本，产生实验层面的测试集过拟合。
4. 计划要求的新协议 legal Joint oracle 没有先完成，就直接进入 v139–v145 实现。
5. 把 `10^-5–10^-4` 的本地差值当成正向证据，归档了过多微版本。
6. 版本在结果产生前就获得最终编号，失败后没有统一回写 `REJECTED/TIMEOUT`，甚至出现两个 v140。

## 3. Linear 的正确数学问题

目标不是分别最小化激活和权重的逐元素 MSE，而是直接求合法 HiF4 编码：

\[
\min_{Q_A,Q_W\in\mathcal H}
\mathbb E\left\|AW^T-Q_A(A;S)Q_W^T\right\|_F^2,
\]

其中 `S` 是校准阶段允许保存的状态，`\mathcal H` 是完整的 HiF4 层级合法集合。记
`E_A=A-Q_A`、`E_W=W-Q_W`，真实输出残差为

\[
R=E_AW^T+AE_W^T-E_AE_W^T.
\]

现有框架的问题是主要优化前两项的局部近似，并没有系统控制三项的方向和抵消关系。

固定部署权重 `Q_W` 时，每行激活的精确二次目标是

\[
J(q\mid a)=qH_Wq^T-2qD_Wa^T+\text{const},
\quad H_W=Q_W^TQ_W,\quad D_W=Q_W^TW.
\]

固定激活集合时，权重误差的度量由

\[
H_A=\mathbb E[A^TA]
\]

决定。逐元素最近舍入只在这些 Hessian 近似对角时合理；当前 64 通道独立 block 近似会丢失
跨 block 相关性。下一阶段必须直接利用 row-space、null-space、低秩谱和合法层级码字结构。

## 4. 先回答 0.8 是否可达：Structural Oracle

这不是版本晋级门槛，而是对问题本身的数学诊断。使用 v86 Linear 作为 parent，在多组互不
重叠的 calibration/test 切分上输出以下曲线：

1. **Weight legal oracle**：固定标准/当前 Activation，直接优化合法 `Q_W`。
2. **Activation legal oracle**：固定 `Q_W`，直接优化每个测试激活的合法 `Q_A`。
3. **Joint legal oracle**：在合法层级码字上交替优化 `Q_W/Q_A`，使用完整输出残差。
4. **Transform oracle**：允许可逆乘积保持变换 `T`，比较 dense、block、butterfly 三种表示上限。
5. **Hierarchy oracle**：比较只改 mantissa、联合 scale/lv2/lv3/mantissa 的上限差。

每个 role/layer 记录：baseline、五类 oracle、有效秩、Hessian 非对角能量、所需时间。最终给出
250 个 Linear case 的完整均值，而不是几个代表层。

### 4.1 必须按形状利用的理论空间

Qwen2.5-0.5B 的 Linear 形状提供了明显不同的空间：

| role | `W` 形状 | `ker(W)` 最小维数 | 理论含义 |
|---|---:|---:|---|
| q / o | 896×896 | 0 | 需要全协方差向量舍入或新坐标系 |
| k / v | 128×896 | **768** | 激活误差可大量推入输出不可见零空间 |
| fc_gate / fc_up | 4864×896 | 0 | 激活侧满列秩，重点优化权重与联合舍入 |
| proj | 896×4864 | **3968** | 激活误差整形的理论空间最大 |

对于任意激活误差 `e`，只要 `e\in\ker(W)`，就有 `eW^T=0`。当前统一 64-block 量化没有显式
利用这一事实。k/v/proj 是最有可能产生数量级提升的 role，不应继续和 q/o/gate/up 使用同一算法。

若完整合法 Joint oracle 在多切分上仍低于 `0.8`，则当前 HiF4 输出约束下没有证据支持目标；
若 oracle 高于 `0.8`，则 oracle 与可部署算法之间的差距会明确告诉我们需要的是表示、舍入还是
层级搜索，而不是继续猜参数。

## 5. 跳出现有框架的 Linear 算法方向

### L1. 零空间/行空间误差整形（NRES，最高优先级）

对 `rows(W)<channels(W)` 的 k/v/proj，只惩罚激活误差在 `row(W)` 上的投影：

\[
e=e_{row}+e_{null},\qquad e_{null}\in\ker(W),\qquad eW^T=e_{row}W^T.
\]

零空间分量不影响输出。算法不再最小化 `\|a-q\|^2`，而是在合法相邻 HiF4 码字中选择一组
相关舍入，使误差尽量落入 `ker(W)`。

实现方式：校准阶段对 `Q_W` 做截断 SVD/QR，保存行空间因子 `B\in R^{r\times C}`；在线以
`\|(a-q)B^T\|^2` 做批量误差反馈舍入。k/v 的真实秩上限只有 128，proj 虽然秩上限 896，
但相对 4864 通道仍有 3968 维零空间。部署采用分块/随机嵌入因子，避免完整 `C×C` Gram。

**理论有效性**：它利用的是输出算子的严格零空间，不依赖某个 alpha 或固定数据上的偶然增益。
零空间给出了连续域中不改变输出的误差方向；合法 HiF4 格点能实现其中多少，必须由 NRES legal
oracle 定量回答，不能仅凭零空间维数宣称可达。

### L2. 子空间嵌入的联合向量舍入（SE-JVR）

当前 BDLR 失败是因为任意选取若干列，所得梯度既不对称，也没有逼近完整输出范数的保证。
新方案对输出空间使用 SRHT/CountSketch：

\[
B=SQ_W,\qquad
\|(a-q)Q_W^T\|^2\approx\|(a-q)B^T\|^2.
\]

当 `S` 是目标误差集合的子空间嵌入时，以高概率保持 `(1\pm\epsilon)` 输出范数。随后在一个
HiF4 64-block 内同时选择多个相邻合法码字，并把已接受舍入误差反馈给后续坐标；这相当于在
Mahalanobis 度量下做向量量化，而不是独立 scalar rounding。

部署复杂度为固定 sketch rank `k` 下的 `O(NCk)` batched matmul，没有完整 `C^2` Gram 和
Python coordinate 循环。`k` 由谱能量和 oracle 误差决定，不通过盲扫参数决定。

### L3. 广义特征分解驱动的乘积保持 Butterfly（GE-BT）

对任意可逆 `T`：

\[
A'=AT^{-1},\qquad W'=WT^T,\qquad A'W'^T=AW^T.
\]

当前 BOAT/ROAB 只在对角或局部 2×2 候选中搜索。新方案从 `H_A` 与 `H_W` 的广义特征问题
构造同时平衡两侧量化噪声的目标坐标系，再把 dense 解投影为固定 stage 的 Givens/butterfly
网络。部署用它**替换**现有 FWHT，而不是叠加第二套变换。

在加性量化噪声、固定码率近似下，输出误差上界由变换后的通道动态范围、`H_A/H_W` 条件数和
噪声协方差决定；广义白化把它变成一个可计算的上界优化目标。真实 HiF4 非连续目标是否受益，
最后由 legal transform oracle 复核。

### L4. HiF4 层级整体 Trellis 量化（HATQ）

HiF4 的 64 通道共享 scale/lv2/lv3，当前算法却主要把 scale 搜索和 mantissa 更新拆开。HATQ
把一个 block 的 `(scale, lv2, lv3, mantissa)` 视为完整合法状态：

1. 根据输出残差生成少量完整层级状态；
2. 在 SE-JVR 的 sketched Hessian 下同时选择 64 个码字；
3. 用 beam/trellis 保留部分和最优状态；
4. 将 calibration 结果编译成有限阈值/决策表，在线不执行完整 beam。

**理论有效性**：共享 scale 使码字选择天然耦合，独立坐标优化不是该离散问题的正确分解；
整体状态搜索严格包含当前层级解，因此离线 oracle 的最优值不会更差。

### L5. 鲁棒联合残差抵消（R-JAQ）

在 L1–L4 得到新表示后，只做固定两轮联合优化：

1. 固定 Activation 规则，按真实 `R` 更新合法 `Q_W`；
2. 固定 `Q_W`，学习输出度量下的 Activation 分段阈值/舍入策略；
3. 在不同 calibration fold 上交叉生成、交叉选择；
4. 目标使用多个 holdout 的均值和最差 fold，而不是同一固定 panel。

动态阶段执行学习后的变换、阈值和一次误差反馈，不进行多轮 `A@W` 搜索。它利用
`E_AW^T`、`AE_W^T`、`E_AE_W^T` 的真实抵消，而不是继续增加 Jacobi/sweep 次数。

## 6. Attention：先冻结 v86，再研究等复杂度新表示

Linear 主线期间，以下 v86 逻辑必须原样保留：Q/K 共享 4/8/16 block-Hadamard、最终量化器
终选、scale-aware K-centering、原始 Q/K/V dynamic 路径。不得再用“v86 级”重写替代。

Linear 得到结构性结果后，Attention 唯一优先方向是 **reciprocal Fisher transform**：

\[
Q'=QR,\qquad K'=KR^{-T},\qquad Q'K'^T=QK^T.
\]

从一阶 Attention 输出扰动

\[
\delta O\approx J_{softmax}(\delta QK^T+Q\delta K^T)V+P\delta V
\]

构造每个 head 的 Fisher/输出敏感度度量，用它求解非正交 reciprocal `R`，再压缩成与 v86
相同 stage 数的 block Givens/butterfly。它替换 v86 的共享正交 Hadamard，连续 logits 严格不变，
动态候选数、Gram sweep 和序列平方循环均不增加。

这条路线的理论收益来自改变 Q/K 联合量化坐标系，不是扫 angle。V 暂时保留 v86；PAWV 和
动态 Q/K Gram 路线已经由 v128–v131 的官方 timeout 关闭。

## 7. 时间设计

v86 官方时间 `222.7s`，有 `77.3s` 真实余量。后续不按本地秒数比例推算官方时间，而按新增
算子结构控制复杂度：

1. Attention 完整冻结 v86，Linear 实验不得顺带改 Attention。
2. 动态 API 禁止序列平方候选循环、完整 `C×C` Gram、逐坐标 Python 循环。
3. NRES/SE-JVR 使用固定秩 batched matmul；GE-BT 替换现有变换；HATQ 的 beam 留在 calibration。
4. calibration 中复用分解、sketch、教师输出和合法码字表，168 次 Weight 调用不重复构造常量。
5. 每次完整实验记录六个 API 的算子次数、tensor shape、FLOP/内存阶和本地时间；官方平台仍是
   `<300s` 的唯一时间裁决。

## 8. 实施顺序

1. **状态整理**：把 v86 标为官方基线；v138/v139 标为通过但失败路线；v140 取消“当前最优”；
   v130/v131 标 `TIMEOUT`，v135–v137 标 `REJECTED`，处理重复 v140。
2. **基线冻结**：从 v86 源码建立一个无改动提交候选，记录 SHA；后续先逐字节复用其 Attention。
3. **Structural Oracle**：在新协议多切分上完成 Weight/Activation/Joint/Transform/Hierarchy 五类
   legal oracle，输出 role/layer 可达曲线和 `0.8` 判断。
4. **L1 NRES**：先做 k/v/proj，因为存在严格大维零空间；完整 250-case 评测后统一记录。
5. **L2 SE-JVR**：覆盖 q/o/gate/up，并与 NRES 共用输出空间 sketch。
6. **L3 GE-BT**：只在 oracle 显示表示变换仍有明显上限时实现，替换旧 BOAT/ROAB。
7. **L4 HATQ**：只解决 oracle 指出的层级码字差距，不再扫旧 scale 网格。
8. **L5 R-JAQ**：组合最有效的表示与舍入，固定两轮联合残差抵消。
9. **官方提交**：先提交“v86 Attention + 单一 Linear 结构算法”，由官方分数判断 Linear 泛化；
   不再同时修改两场景。
10. **Attention 新表示**：Linear 主线稳定后，再单独提交 reciprocal Fisher transform 消融。

## 9. 版本与归档规则

1. 参数、阻尼、rank、seed、角度和 sketch 尺寸的内部试验只写一个汇总 JSON/日志，不分配版本号。
2. 只有新的数学算法、官方提交代码或保留的代表性失败算法才进入 `solutions/`。
3. 最终目录名必须包含结果状态：`retained`、`rejected` 或 `timeout`；`result.md` 首行状态一致。
4. 失败微变体删除源码，只保留汇总 JSON/日志；代表性失败保留一个带 `rejected` 的源码快照。
5. 版本号全局唯一；禁止再次出现同一编号对应两个目录。
6. 官方分数、官方时间、本地均值、本地时间分字段记录，绝不互相换算。

## 10. 当前结论

- 官方最优和下一阶段基线是 **v86**，不是 v140。
- v138–v145 证明当前局部调参/叠模块路线失败，应关闭。
- Linear `0.8` 尚未被当前协议的合法 Joint oracle 证明；在 oracle 完成前不能继续宣称某条实现
  “可能到 0.8”。
- 真正有理论空间的方向是：**零空间误差整形 + 输出度量联合向量舍入 + 广义特征乘积保持变换
  + HiF4 层级整体量化 + 鲁棒联合残差抵消**。
- Attention 不再压缩 v86；后续只研究保持 logits 不变、替换现有变换的 reciprocal Fisher 表示。
