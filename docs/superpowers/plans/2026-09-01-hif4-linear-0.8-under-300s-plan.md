## 1. 现状重判

17816 比 v86 的 16744 高 **1072 分**，并且用户已经确认增益来自一套新的 Linear 算法。
这说明此前 v138–v145 的失败不能推出 Linear 难以提升，只能推出那条“局部 output gain、pair
transform、选列 BDLR 和缩减 Attention”路线失败。

新算法已经给出三个重要证据：

1. Linear 的主要问题确实是量化坐标系和误差传播，而不是单纯增加候选数量；
2. 激活与权重必须在同一个输出重构度量下优化，逐元素 MSE 不是正确目标；
3. HiF4 的 scale/lv2/lv3/mantissa 离散结构仍有明显可利用空间。

目前不能仅凭总分 17816 宣称 `linear_mean >= 0.8`。官方总分的场景权重未公开，Attention
配置和新提交运行时间也尚未记录。正确问题已经从“这条方向有没有效果”变为：

- 哪个结构产生了官方增益；
- 还剩多少可消除的 Linear 输出误差；
- 如何保留这些增益并把动态复杂度控制在官方 300 秒内。

## 2. 当前新算法的统一数学描述

设原始权重为 `W`，校准激活为 `X`。算法先选择作用于输入通道的可逆等价变换 `R`：

\[
X'=XR,\qquad W'=WR^{-T},\qquad X'W'^T=XW^T.
\]

按当前动态阶段的执行顺序，`R` 可以写成

\[
R=D^{-1}PS,
\]

- `D^{-1}`：激活侧 SmoothQuant 逆缩放，权重侧对应使用 `D`；
- `P`：通道置换；
- `S`：4/8/16 block signed-Hadamard 正交变换。

变换本身在连续域中不改变 Linear 输出。它的作用是改变 HiF4 离散格点相对于数据分布和
输出 Hessian 的方向，使量化后的 `Q_X Q_W^T` 更接近 `XW^T`。

最终应优化的目标是

\[
\min_{R,Q_X,Q_W\in\mathcal H}
\mathbb E\|XW^T-Q_X(XR)Q_W(WR^{-T})^T\|_F^2,
\]

其中 `\mathcal H` 是合法 HiF4 层级码域。记 `E_X=X'-Q_X`、`E_W=W'-Q_W`，真实残差为

\[
R=E_XW'^T+X'E_W^T-E_XE_W^T.
\]

新算法比 v138–v145 更有效的根本原因，是它同时处理了坐标系、跨块误差传播和层级离散码字，
而不是只修改其中一个局部近似。

## 3. 已确认的新算法框架

### 3.1 校准统计

从 NVFP4 校准激活恢复 FP32，统计：

- 通道二阶矩 `E[X_c^2]`；
- 通道 `amax`；
- 需要 GPTQ 时的完整协方差 `H_X=E[X'^T X']`；
- 少量 proxy token 和独立 e2e token。

协方差必须在最终候选变换后的坐标 `X'` 上使用。若先计算原坐标 Hessian，则应用变换后必须
严格做合同变换，不能把不匹配坐标系的 Hessian 交给 GPTQ。

### 3.2 SmoothQuant 与 Permutation

SmoothQuant 候选为

\[
d_c=\frac{(amax_{x,c}+\epsilon)^\alpha}
{(amax_{w,c}+\epsilon)^{1-\alpha}},
\]

并包含 RMS 版本。实际应用 `W'=W*d`、`X'=X/d`，连续乘积保持不变。

Permutation 根据激活/权重 `log(range)` 的联合、weight-only 或 activation-only 排序生成候选，
但实际选择出的同一个置换必须同时作用于 X 和 W。它的作用是降低每个 64-channel HiF4 block
内部的动态范围异质性，而不是改变模型通道语义。

### 3.3 Block Hadamard 与联合搜索

在 Smooth+Permutation 后尝试 4/8/16 block signed-Hadamard。正交变换重新分布异常值和相关性，
又不改变连续输出。窄层对 `smooth × permutation × Hadamard` 做联合 e2e 搜索是必要的，因为：

\[
\arg\min_T L_{proxy}(T)
\]

不必等于最终量化器下的

\[
\arg\min_T \|XW^T-Q_X(T)Q_W(T)^T\|^2.
\]

因此 e2e 输出 MSE，而不是 operand MSE，才是最终选择依据。

### 3.4 Weight GPTQ

固定变换后，权重量化的二次目标由校准激活 Hessian 决定：

\[
L_W(Q_W)=\mathrm{tr}((W'-Q_W)H_X(W'-Q_W)^T).
\]

逐 64-block 量化后，使用正则化逆 Hessian/Schur 补把当前量化误差补偿到尚未量化的列。
与独立 block 量化相比，GPTQ 利用了后续通道自由度抵消前面已经产生的输出误差。

这里真正重要的不是“打开 GPTQ”这个开关，而是：

1. HiF4 64-block 必须作为原子量化单元；
2. 误差更新必须与 block 顺序和变换后的 Hessian 一致；
3. 每个已选 block 必须是完整合法 HiF4 编码，而不是连续近似后再投影。

### 3.5 Activation GPTQ

部署权重 `Q_W` 固定后，每个激活向量的精确输出度量为

\[
L_X(q\mid x')=(x'-q)H_W(x'-q)^T,
\qquad H_W=Q_W^TQ_W.
\]

因此动态 Activation GPTQ 使用 `(H_W+\lambda I)^{-1}` 逐 64-block 误差反馈，比按激活自身
逐元素 MSE 量化更符合最终 Linear 输出。这里应优先使用实际部署的 `Q_W` 构造 `H_W`；若使用
FP32 `W'`，会重新引入训练目标与部署目标错位。

### 3.6 HiF4 层级离散优化

当前 `_dense_to_hif4` 已经把以下结构纳入选择：

- 64-channel E6M2 `scale_factor`；
- 8-channel lv2 二倍开关；
- 4-channel lv3 二倍开关；
- 3-bit mantissa 与 sign；
- quadratic AdaRound；
- scale offset `(-1,+1,+2,+3)`；
- 高损失块自适应 refine；
- 命中搜索边界后的 edge extension。

这比只优化 mantissa 更接近 HiF4 的真实离散问题。它也解释了新算法为什么可能在官方隐藏集
泛化：优化依据是输出二次型和合法码域，不是固定样本上的连续 gain。

## 4. 为什么该算法理论上有效

### 4.1 等价变换降低量化条件数

Smooth、Permutation 和 Hadamard 都保持连续乘积，但改变通道动态范围、相关性和共享 scale
分组。HiF4 的主要误差来自 64/8/4 层级共享尺度；降低块内幅值跨度会直接减小量化步长浪费。

### 4.2 GPTQ 是有目标的误差反馈

若把剩余未量化通道记为 `R`、当前 block 记为 `B`，GPTQ 不是简单把误差平均扩散，而是利用
Hessian 的条件结构选择最小化二次损失的补偿。它解决的是旧方案完全没有处理的跨 64-block
耦合。

### 4.3 双侧输出度量匹配真实任务

Weight GPTQ 使用 `H_X`，Activation GPTQ 使用 `H_W`。两者分别在对方定义的输出度量下
优化，因此比 operand MSE 更接近 `XW^T`。这是新框架最可能带来 1072 官方分提升的核心结构。

### 4.4 e2e 搜索减少代理目标错位

旧路线多次出现本地代理上升、官方下降。新算法至少在变换选择阶段使用输出重构 MSE，并对窄层
联合搜索变换组合，减少了“单项看起来更好、组合后反而更差”的风险。

### 4.5 理论边界

上述性质证明算法方向合理，但不能证明 `linear_mean=0.8` 必然可达：

- HiF4 合法码域是非凸离散集合；
- GPTQ 是顺序贪心/局部二次近似，不是联合全局最优；
- Weight 与 Activation 目前仍是分阶段优化，交叉项 `-E_XE_W^T` 没有被完全求解；
- 完整逆 Hessian 的动态代价可能与 `<300s` 冲突；
- 17816 是总分，不是公开的 Linear mean。

因此 0.8 的可达性应通过新框架内的离线上限实验判断，而不是回到旧框架继续扫 alpha。

## 5. 下一步算法方向：沿新框架扩大有效部分

### A1. Block-Schur HiF4 GPTQ

把 64-channel HiF4 block 作为整体变量，使用 block Schur complement 执行误差补偿。当前 block
量化器负责生成完整合法候选，Schur 更新只负责把已接受残差传播到未量化 block。

这比逐坐标 GPTQ 更匹配共享 scale/lv2/lv3 结构，也能避免某个坐标先量化后破坏同一 HiF4
block 的 scale 选择。候选评分直接使用完整二次增量，不增加新的经验参数。

### A2. 低秩加块对角的 Activation GPTQ

完整 `H_W^{-1}` 的存储是 `O(C^2)`，动态顺序补偿最坏也是 `O(TC^2)`。这对 `C=4864` 的
proj 层可能成为官方时间主风险。

将

\[
H_W\approx B+UU^T
\]

其中 `B` 是 64-block 对角，`U` 保留跨 block 主特征。利用 Woodbury 公式保存 `B^{-1}` 和
低秩因子，在线复杂度降为固定 rank 下的 `O(TCk)` 加 block 运算。rank 由谱累计能量确定，
不是盲扫。它保留 GPTQ 最有价值的跨块方向，同时控制时间。

### A3. Joint Weight–Activation 交替优化

当前流程先定 `Q_W`，再定 Activation 策略。下一步在 calibration 上做固定两轮：

1. 用当前 Activation 量化规则生成 `Q_X`；
2. 按完整残差 `R` 重新优化合法 `Q_W`；
3. 用部署 `Q_W` 重建 `H_W`，重新生成 Activation GPTQ 状态；
4. 在独立 e2e token 上选择第一轮或第二轮结果。

它直接利用双侧误差的抵消关系，不通过增加动态 sweep 次数实现。

### A4. 学习型结构化等价变换

当前 `D/P/Hadamard` 是有限候选集合。保留相同部署算子数量，把固定 Hadamard 替换为少量 stage
的 signed butterfly/Givens 结构，并在 calibration 上最小化完整 HiF4 e2e loss。

训练只在校准阶段进行，动态阶段仍是一套固定结构变换。若最终结构与当前 Hadamard stage 数相同，
它提高表示能力而不改变渐近复杂度。

### A5. Role-specific 求解器

不同 Qwen Linear 形状不应使用相同预算：

| role | 结构 | 优先算法 |
|---|---|---|
| k/v | `128×896` | 低秩输出度量、Activation 误差整形 |
| q/o | `896×896` | 完整 block-Schur、学习型变换 |
| gate/up | `4864×896` | Weight GPTQ、联合 Smooth/Permutation |
| down/proj | `896×4864` | 低秩+块对角 Activation GPTQ、严格时间优化 |

预算依据是矩阵秩、Hessian 谱和该 role 的输出损失占比，而不是宽层/窄层两个粗阈值。

### A6. 层级码字联合候选

当前 offset/refine 已搜索部分 scale code。下一步让 GPTQ 的 block oracle同时生成
`scale/lv2/lv3/mantissa` 的完整候选，用小 beam 保留少量层级状态，再由 block 二次型选择。
beam 只用于 calibration Weight；动态 Activation 使用校准后编译出的阈值与候选表，避免在线搜索爆炸。

## 6. 必须做的算法归因实验

这不是设置额外门槛，而是避免再次不知道 17816 为什么成立。所有内部变体写入同一实验记录，
不为每个变体建立版本目录。

### 6.1 组件消融

保持同一 Attention 和同一评测数据，依次记录：

1. 新框架完整版本；
2. 去掉 Weight GPTQ；
3. 去掉 Activation GPTQ；
4. 去掉完整 covariance，只保留 block quadratic；
5. Identity / Smooth / Smooth+Perm / Smooth+Perm+Hadamard；
6. 去掉 offset/refine；
7. proxy 选择与 e2e 选择的差值。

目的不是挑一个微小增益版本，而是把 1072 官方分对应到变换、Weight GPTQ、Activation GPTQ
和层级码字优化四类结构。

### 6.2 Role 消融

分别只在 q、k、v、o、gate/up、down/proj 启用新 Linear 算法，记录各 role 的：

- 输出 MSE 改善；
- Weight/Activation 各自改善；
- API 时间；
- Hessian 有效秩和 block 外谱能量。

这会直接决定 A1–A6 的计算预算投向，而不是继续全层统一增加复杂度。

### 6.3 可达性曲线

在新框架上计算四条离线曲线：

1. 仅最优变换；
2. 变换 + Weight block oracle；
3. 变换 + Weight/Activation 分别 oracle；
4. 变换 + Joint Weight–Activation oracle。

若 Joint oracle 的多切分 `linear_mean` 明显超过 0.8，则 0.8 有明确算法空间；若 oracle 本身
仍低于 0.8，下一步应扩展变换/码字表示，而不是增加 GPTQ 迭代次数。

## 7. 时间方案

新版本官方时间尚未提供，因此当前只确认“精度有效”，不确认“两个目标都已完成”。拿到源码后
首先按六个 API 分解时间：

- Linear calibration：协方差、候选 e2e、矩阵求逆、Weight GPTQ；
- Linear dynamic：变换、Activation GPTQ、quadratic refine；
- 原 Attention calibration/dynamic；
- state 大小和 host/device 搬运。

时间优化按算子结构执行：

1. 完整逆 Hessian只在 calibration 计算一次；
2. dynamic 不保存/乘完整 `C×C` 逆矩阵，优先 A2 低秩+块对角形式；
3. Transform 联合搜索只在 calibration，部署只执行胜出的一次变换；
4. 动态 refine 使用编译候选表和批量 tensor 运算，不做 Python 逐坐标/逐候选循环；
5. Attention 在 Linear 归因期间保持产生 17816 的原样实现，不同时改两个场景；
6. 官方平台仍是 `<300s` 的唯一时间结论，本地只记录算子和同机 A/B。

## 8. 执行顺序

1. **接收并冻结 17816 源码**：记录版本号、SHA、官方时间和对应 Attention；归档为新官方锚点。
2. **本地复现**：用更新后的本地评测记录 Linear/Attention 均值和六 API 时间，不反推官方权重。
3. **组件与 role 归因**：一次实验记录完成 6.1/6.2，不生成十几个微版本。
4. **复杂度重构**：若 Activation GPTQ 是主要动态成本，先实现 A2；若不是，不无意义改写。
5. **精度主线**：按归因结果实现 A1、A3、A4、A6 中贡献空间最大的结构。
6. **0.8 可达性曲线**：在新框架而不是旧 v86 框架上运行四级 oracle。
7. **官方单变量提交**：保持 17816 对应 Attention 不变，只替换一个新的 Linear 结构算法。
8. **Attention 后续**：Linear 达到稳定点后，再独立研究 Attention；不与 Linear 新算法混交提交。

## 9. 版本与归档规则

1. 17816 的真实源码到位后立即建立一个 `retained` 官方快照，记录官方分数和时间。
2. 内部 alpha、rank、seed、offset、block size 和 refine ratio 不单独分配版本号。
3. 一个新的数学求解器只保留完整算法版本和一个代表性失败版本。
4. 目录名与 `result.md` 必须写 `retained/rejected/timeout`，版本号全局唯一。
5. 官方总分、官方时间、本地 Linear/Attention、本地六 API 时间分别记录，不互相推算。

## 10. 当前结论

- **17816 已经证明新 Linear 框架在官方隐藏评测上有效。**
- 主要理论机制是：等价变换重构量化坐标系、双侧 GPTQ 输出误差反馈、HiF4 合法层级码字优化。
- 当前最值得扩展的不是 Smooth alpha，而是 block-Schur GPTQ、低秩+块对角动态 Hessian、双侧
  联合残差优化和相同复杂度的学习型结构变换。
- `linear_mean=0.8` 比此前更可信，但仍需要新框架下的 Joint oracle 或实际分项结果证明。
- 官方 `<300s` 是否满足仍缺少新提交时间；在记录该事实前不能声称时间目标已经完成。
