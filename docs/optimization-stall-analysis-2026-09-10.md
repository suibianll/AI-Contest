## 结论

根仍为 18053/281s，距用户提供的榜首锚点 21765 差 3712 分；距成功机制锚点 21071 差 3018 分。
两锚点都缺少可绑定源码，不能把差距归因到某侧或承诺某机制能补齐。
持续没有官方晋级，主要是目标/近似与部署不一致、有效下降成本高、官方反馈未闭环，以及执行规则反复漂移。
这不等于量化空间已饱和：最新 L-EM1/L-EM2 已有明显的真实硬输出改善，尚不能据此宣称官方突破。

## 1. 算法没有稳定地优化同一个真实部署问题

- L-XR1 用低秩块外度量和冻结梯度，记录显示 offblock_rel 中位 0.82、rank-4 仅捕获 39%；
  shard0 被触及的 40 case 全负。忽略跨块耦合使局部便宜的码变化实际很贵。
- A-RB1 虽经有限差分验证梯度，但共享边界同时改变大量元素，对角曲率未捕获联合影响；
  实际输出 MSE 恶化 1.07–2.97 倍，最终全回退。正确梯度不保证大范围离散提议正确。
- L-JRB1 在 5/7 层型未查询新边界表，代码走 `_adaround_mantissa`；写了算法不等于覆盖了部署路径。
  另外 2/7 层型可达仍未获最终输出接受。这只能否定该实现。

证据：[计划入口的已完成卡记录](superpowers/plans/README.md)、
[L-XR1 归档计划](superpowers/archive/plans/2026-09-10-linear-cross-residual-correction-plan-rejected.md)。

当前根同样存在训练/部署差别：`solution.py` 的 `_a2_train_rotation` 用 `_dense_to_hif4(q_rot/k_shift)`
训练，最终 `_a2_true_path_gate_loss` 再检查完整部署路径；后者只使用最后一个 calibration window。
代码把量化后的输出梯度直接回传到连续 rotation/center，属于替代梯度，不能保证真实离散损失下降。
这是结构性风险的代码证据，不是对当前根官方损失的定量归因；v222 修正尝试官方反而下降，也不支持贸然替换根。

## 2. 已找到更有效目标，但实现成本成为瓶颈

[L-EM1 记录](../logs/execution/2026-09-10-linear-exact-metric-refinement.md)报告：
真实输出代价恒等式校验通过，shard0 `delta_mean=+0.107791`、48/0/8；
同进程动态配对新增约 0.5671s/call，逐组大量小算子派发是明确的本机成本问题。
[L-EM2 记录](../logs/execution/2026-09-10-linear-groupstep-schedule.md)报告：
组号主序调度 shard0 `+0.088372`、48/0/8，以较少顺序迭代保留约 82% 的该 shard 指标增量。
这些是本地实际输出证据，既非官方分数换算，也非全六 shard 或官方结果。

因此 Linear 优先方向应是保留精确交叉残差目标与联合接受校验，减少执行开销；
不再退回已证实失真的低秩/冻结梯度近似，也不单凭少数 case 推断普遍单调性。

还有必须处理的实现边界：L-EM1 implementation 的动态路径实际执行 Cholesky 求逆，
计划却写“动态无矩阵分解”；L-EM2 文档也保留动态重建逆。
它与 AGENTS 禁止动态完整求逆冲突。建议在后续实现任务中把度量构造移到校准，审查状态内存和传输，
尽量复用已有状态或精确分解，避免盲目额外复制每状态 n² 矩阵。
这是具体架构问题，不能仅以合法五字段通过就视为全部执行约束通过。

`+0.014923`、26/10/36；官方回传为完整包 TIMEOUT 且侧隔离 `14424/245s`（−2），本地正向
未迁移官方，K 平移类正式关闭。该反转再次确认本地六 shard 符号不能为同一路线晋级。
Q 定心不同：`mean(Q)K^T` 随 key 改变，无同样的不变性保护，不能从 K 的正向类推 Q；不应作为主要突破方向。
