# 勘误：Attention 输出级目标与"跨 API 信息墙"（2026-09-10）

> 类型：**对既有结论的勘误**。不改写任何原始报告/日志；本文为新增更正记录。
> 触发：用户指出赛题反作弊条款的范围，要求修复该赛题信息以免继续误导后续优化。

## 1. 被勘误的说法

本轮多次出现、并被用于关闭机制的两句话：

1. "`hif4_dynamic_quantize_q/k/v` 相互独立，看不到另一个操作数、也看不到 softmax。"
2. "最优码选择恰恰需要它们，所以赛题的合法执行模型排除了最优算法。"（先记为 `API_INCOMPATIBLE`）

**两句都不成立。** 第 1 句把函数签名约束说成了执行隔离；第 2 句把第 1 句升格成赛制禁令，
而赛题原文**没有**这条禁令，且**明文要求相反的做法**。

## 2. 赛题原文（`赛事说明书.txt`，逐行核对）

**L180（Attention 场景，目标定义）：**

> **Attention场景：** 利用校准Q、K、V数据生成在线量化所需状态，并分别对在线Q、K、V进行动态HiF4量化，
> 使量化后的 $Attention(Q_{HIF4}, K_{HIF4}^T, V_{HIF4})$ 与原始NVFP4数据反量化后计算得到的
> $Attention(Q_{NVFP4}, K_{NVFP4}^T, V_{NVFP4})$ 之间的 **MSE 尽可能低**

→ **输出级目标就是赛题对 Attention 的书面要求**，而且**指定用校准 Q/K/V 生成 state**。

**L191（§2.3 第 4 条，位于 Linear 段 `activation_state` 之下）：**

> 不允许以任何形式计算出A@W，并利用A@W进行拟合反推出**Q(A)**，违背比赛初衷。
> 工作组会对选手提交的代码进行审核，出现该行为视为弃赛。

→ 三个成分合起来才构成禁令：**计算 A@W** + **用它拟合** + **反推出 Q(A)**。
对象是 `Q(A)`——**Linear 侧的激活量化器**。理由是"违背比赛初衷"（初衷是设计量化算法，不是从答案反解）。
**全文没有第二条反作弊条款。**

**L192 / L193（Attention 校准与传参）：**

> 5. …输入若干组NVFP4格式的校准Q、K、V数据以及Head相关参数，得到后续在线量化使用的 q_state、k_state 和 v_state…
> 6. …**选手可自定义传参内容以及传参处理方式**…

**L195（Attention 在线测试）：**

> 8. 对于每组测试Q、K、V数据，**分别调用** …q/k/v，并传入**对应校准状态**

→ 约束的是**调用形式与传参内容**，没有一句话约束进程内状态或跨调用通信。

**L208（§2.4 注）：**

> 注：除了本节明确定义的文件和函数之外，不允许选手在代码中进行文件读写操作，
> **对其他数据结构和函数接口及实现不作限制。**

→ **封闭列举**：明文两条禁令（文件 I/O、A@W 反解 `Q(A)`）+ 一句"其余不作限制"。

## 3. 正确读法

| 命题 | 判定 | 依据 |
|---|---|---|
| 动态 API 的**参数表**里只有自己的 Q/K/V 与对应 state | **成立**（赛题硬约束） | L195；`evaluator/official_eval.py:2693/2699/2705` 实测调用 |
| 动态 API **执行期相互隔离**、不得共享进程状态 | **赛题未规定** | L208"不作限制"；全文无此条款 |

| 用校准 Q/K/V 学耦合规则并编译进 state | **赛题明文要求** | L180："利用校准Q、K、V数据生成在线量化所需状态" |
| ~~Linear 侧用 A@W 反解 `Q(A)`~~ | **已失效（2026-09-11）** | ~~L191~~ |

**"不能偷读另一 API 本次输入、不利用调用顺序"仍然是有效纪律，但身份是本仓库为可审计性自设的自律条款，不是赛制禁令。** 不得再用它关闭机制设计，也不得再把它当作"物理定律"引用。

## 4. 该错误导致的既有结论（后续不得援引）

以下结论都建立在被勘误的第 2 句之上，**均须视为无效归因**：

- "A-JC1 主线记 `API_INCOMPATIBLE`"——已于 2026-09-10 经用户审读撤回（`report-080-verdict.md` §5.2），本次补充其**来源本身**也不成立。
- 以"需要联合信息"为由否决的任何 Q/K 或 V 侧输出级机制。
- `proposals/2026-09-10-attention-080-algorithm-research-next.md` §3 第 0 项"第一道闸门"的**判据**：其问法（联合信息能否压成规则）仍是有用的设计检查，但**答不出不等于接口不兼容**，只等于该形式不可部署；正确处置是改用"校准期编译"的形式。
- §3 第 4 项 `API_INCOMPATIBLE` 的适用范围（已在计划内就地收窄）。

## 5. 修复后的操作规则（供后续计划直接引用）

1. **准入判据**：`API_INCOMPATIBLE` **仅**适用于"部署表达式无法由本次输入 + 编译 state 算出，**且**该校准期无法用 Q/K/V 编译出等价规则"。**"需要联合信息"本身不是拒绝理由。**
