# v130 official timeout update

用户于 2026-09-01 确认：v130 在官方评测中超时，耗时 `>300s`，没有返回官方分数。

v130 的本地 `official-shape-v1` 记录为：Linear `0.471837`、Attention `0.836579`、
API `295.437s`、wall `317.607s`。因此本地总 API 小于 300 秒不能作为官方通过条件。

## 时间归因

| 候选 | 本地 Attention calibration | 本地动态 Q/K/V | 本地 API total | 官方结果 |
|---|---:|---:|---:|---|
| v084 | 43.817s | 5.283s | 279.191s | 252.563s pass |
| v086 | 55.347s | 5.761s | 299.302s | 222.7s pass |
| v129 | 126.415s | 35.138s | 248.363s | timeout |
| v130 | 115.461s | 34.459s | 295.437s | timeout |

这组事实不支持用一个固定比例把本地秒数映射到官方秒数：v86 本地更慢却通过，
v129 本地更快却超时。更可信的工程解释是，v129/v130 的 Attention calibration
候选循环和动态 Q/K Gram 精修在官方硬件/运行时上的算子放大倍数更高；v86 的
C86 静态 block-Hadamard 路径没有该代价。

后续时间策略：Linear 精度改动继续保留，但 Attention 先回到 v86 级别的静态、低
调用复杂度，再逐步恢复精度组件；所有本地评测只作算子/调用计数对比，不再宣称
`api_total<300s` 等价于官方通过。
