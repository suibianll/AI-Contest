# OOD 门禁修订（2026-09-07）

用户明确要求修复可能误判方向的门禁。本记录取代历史文档中的 OOD 一票否决规则；不改写原始实验 JSON/report 或历史官方结果。

## 证据与边界

- Attention R2c 官方 14387.8 / 240s，相对 R1 14009 / 211s 增加 378.8 分；同一候选本地 Δgap=+0.012242 曾触发 OOD 禁止门。
- 官方计分源码由 R2c manifest 绑定 SHA `CFDDCED7886A0CABC7251C57387536B86169185E7A6D8BE7A8647FEFAE677CD6`。
- 该反例证明固定阈值会误拦，不能据此推导新的安全阈值或宣布 OOD 无价值。

## 当前规则

1. OOD 是必须完成的配对风险诊断，使用候选与直接父各自同 SHA 的 ID/OOD 结果，协议与面板须匹配。
2. 分别报告 ID Δgain、OOD Δgain、Δgap=ID Δgain−OOD Δgain，以及负向 case 和最坏分组。负 Δgap 表示 OOD 增益更多，正 Δgap 不等于 OOD 退化。
3. `|Δgap|>0.01` 仅为收益不对称提示；OOD 实际退化另记风险。二者均不单独禁止官方探索，不需逐候选申请豁免。
4. 其他合法性、control、校准/验证隔离、有效本地门、时间和固定配置约束不变；校准拟合标签仅提示风险，不单独阻止探索。
5. 分析器的 eligible_for_official_review 仅为本地建议，不能替代完整提交检查；正式晋级仍须官方分数、时间和源码身份确认。
6. 仅因 OOD 被拦的历史结果不能证明方向无效，应解释为缺少官方验证；不自动重跑历史候选，不重开已有官方负结果或其他有效失败边界。
