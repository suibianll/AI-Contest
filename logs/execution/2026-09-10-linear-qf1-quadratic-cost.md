## 1. 缺陷：局部代价不是它以为的那个量

`_em1_dynamic_descent` 用局部 Gram 给 8 个 pm1 候选定价，父式：

```python
quadratic = torch.einsum("krba,bij,krbj->krb", delta, local_gram, delta)
```

两个求和指标**各自只出现在一个操作数里**：`a` 只属于第一个 `delta`，`i` 只属于第二个
`local_gram`（`j` 同时属于 `local_gram` 和第二个 `delta`）。所以 `a` 与 `i` 从不相遇，
收缩出来的是

```
(Σ_a delta_a) · Σ_j (Σ_i G_ij) delta_j   =   1ᵀδ · (colsum G)ᵀ δ
```

而不是 `δᵀGδ`。正确写法要让第一个操作数按 `local_gram` 的**行指标**索引：

```python
quadratic = torch.einsum("krbi,bij,krbj->krb", delta, local_gram, delta)
```

这不是"等价重结合"。`krbi,bij,krbj->krb` 是本文件自己的写法——权重编码器在
`solution.py:1983` 就是用同一串收缩 `e^T H e` 的；父根在局部代价这一处走了另一条路。

### 1.1 在真实候选集上退化成什么

8 个 pm1 候选全部是**单坐标**的：`element_index=[0,0,1,1,2,2,3,3]`，
mask 只在一个位置为真，`torch.where(mask_row, moved, code_g.unsqueeze(0))`。
所以 `δ = c·e_m`（`c = ±0.25`），两种写法分别退化为

| | 父式 | 正确式 |
|---|---|---|
| `c·e_m` 的代价 | `c²·colsum(G)[m]` | `c²·G[m,m]` |

也就是说，父根实际比较的是"列和"，而列和**并不是**该坐标移动的代价。

### 1.2 反例（`verify.py` control Q4/Q5）

`Q4`：`G=[[2,1],[1,3]]`（对称正定），`δ=[1,0]`。真值 `δᵀGδ = 2`，
父式 `= 3`。同一个位移，父根多报 1.0，**方向偏保守**。

`Q5`：`G=[[1,-2],[-2,10]]`，特征值 `0.5756 / 10.4244`（正定），但第 0 列列和 `= -1`。
`δ=[1,0]` 时真代价 `+1.0`（应拒绝），父式报 `-1.0`（应接受）。
**正定 Gram 可以有负的列和**，于是父式会把一次真实的增损当成收益接受。

> **口径说明（重要）。** Q5 只证明"父式在数学上可能反号"，**不表示它在真实数据上反号**。
> 真实 layer0/q 的 2560 个局部 Gram 里，列和为负的有 **0 个**
（`[D:real/layer0/q] local grams with a negative column sum: 0/2560`）。
在这块数据上缺陷的实际后果是**量级误排**，不是符号翻转：
8 个候选里 5.94% 的提议槽位选出了不同的候选，接受判决有 5491 处不同。
反例是"公式错了"的证据，不是"实际已经翻车"的证据。

## 2. 修正后局部代价就是目标差本身（不再是近似）

`J(X) = ‖(X - T)Ŵᵀ‖²` 对 `X` 是二次的，所以

```
J(x+d) - J(x) = 2·∇J·d + dᵀGd
```

是**恒等式**，不是二阶近似。`Q3` 用 float64 稠密矩阵乘独立算 `J(x+d) − J(x)`：
修正式相对误差 `4.767e-15`（fp 地板），父式 `5.439e-02`。
即修正之后，接受判决里的"代价"与真实目标差**逐位一致**；修正之前不是。
`Q6` 另证组块（4×4）定价与全度量定价一致（`rel=1.122e-16`），
这也是"只在组块上算二次型"这一步本身成立的前提。

## 3. 候选构建：改动由机器测量，而不是由人声明

`workbench/full_solution/linear-qf1-quadratic-cost/build.py` **不手写**覆盖函数，而是：

1. 从父根字节里切出 `_em1_dynamic_descent` 的源码；
2. 只替换一个子串 `krba,bij,krbj->krb` → `krbi,bij,krbj->krb`；
3. 把这段文本（加注释头）追加到父根之后。

于是"唯一改动"是可测量的：`build.py` 统计父函数文本与追加文本的**逐字节差异数**，
不等于 1 就拒绝构建。本次实测：

| 项 | 值 |
|---|---|
| `extracted_function_differing_bytes` | **1** |
| 父根 | `0f1af6db…` / 505496 B |
| 追加实现 | `daddc5bb…` / 9533 B |
| 候选 | `447f815ac7bee74950a352cac64e1489cef39fa4c52102c1f902f940579684ca` / 515031 B |

`_em1_dynamic_descent` 由父根的 `hif4_dynamic_quantize_activation` 在**调用时**从模块
全局解析（其 `co_names` 含该名字），所以追加定义会遮蔽父定义，而父根两个 hook
一行都不用碰。候选里唯一的变化是"父定义变成死代码"。

## 5. 时间

**本卡不加时间。** 改的是一串下标，`einsum` 的操作数形状、步数、循环结构一个未变。

shard0 同进程配对（同一次校准下交替计时）：候选动态 API `42.216 s / 56 calls`，
基线 `43.106 s / 56 calls`——候选略快，不慢于父。
`build.json` 里 `extracted_function_differing_bytes = 1` 是这次"零时间成本"的机械证据：
只动了一个字符，没有引入任何新算子。

> 父根的 `api_total` 与本候选的 `api_total` **不可比**：候选 SHA 变了，校准缓存冷启
> （131.893 s 全价），基线走的是缓存命中。只有上面的"动态 API 单独"口径是同条件的。

## 7. 裁决

**LOCAL_POSITIVE_PENDING_OFFICIAL。** 归档为 **v232**
（`solutions/20260910_v232_linear-qf1-quadratic-cost_scoreNA_timeNA/`）。

计划 §2 预先写定："若合法可达且非等价，归档单一代表交官方"。本机制**可证非等价**
（仅 shard0 就有 48 个非零 case），所以归档路径在读到六 shard 数字之前就已确定；
六 shard 数字只用于记录量级与回退分布，**不作为官方提交门**。

- **不加时间**：`extracted_function_differing_bytes = 1`，同进程配对夹住零。
  不写官方秒数预测——本地测量无法定官方秒数。
- **不重试**：官方下降/超时只关闭本修正代表，不反复改候选数/阈值/组粒度。
- **血统**：v232 是 v230 的后代，**不含** v231 的 K=2 机制。v231 是 v230 的兄弟臂。
  两者的本地 Δ **不可相加**当作官方预测；将来若两者都官方正向，再从较高分完整父重建组合。
- 父根（v230 计分源码）本卡未动，仍为 `0f1af6db`。

归档后按计划 §1 的顺序进入第二卡 **L-TF1**（复用首遍梯度）。
