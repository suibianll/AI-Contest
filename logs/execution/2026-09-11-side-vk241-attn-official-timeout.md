## 2. 它证明了什么

**VK 核机制仍然一个官方分都没有。** 现在两条通道都是硬失败：

| 通道 | 形态 | 结果 |
|---|---|---|
| 完整包 | v237 根 + VK（per-Q-head） | `TIMEOUT`（[登记](2026-09-11-v241-v242-vk-official-timeout.md)） |
| 完整包 | v237 根 + VK（per-KV-group） | `TIMEOUT`（同上） |
| **侧隔离** | **标准 Linear + VK（per-Q-head）** | **`TIMEOUT`（本文）** |

侧隔离是在**标准 Linear 地面**上跑的，与 v195 探针同底，唯一差异是 Attention 侧换成 VK。
v195 用 `+5s` 换来 `+21` 分，说明这个通道在**便宜机制**上余量充裕；换成 VK 之后
连 300s 硬限都没进。

**一个下界，不是一次测量**：探针时间 `> 300s`，而 v195 是 `243s`——硬限是确切的，
所以 VK（per-Q-head）在侧隔离口径上相对 v195 的 Attention **至少多花约 57 s**
（相对 R3 基线 `238s` 至少多花约 62 s）。这个不等式方向要翻转需要 57s 量级的时间波动。
**但本记录不由此推出任何"需要省 N 秒"的预算或优先级**（AGENTS §2：官方秒数带未量化的
波动，"余量/需要省 N 秒"不构成研发预算或优先级依据）。它只记录一个硬失败。

## 3. 它证伪了什么（本次真正的方法论收获）

**证伪的是我开这条通道时用的前提。**

开探针的原始理由是（[构建记录](2026-09-11-vk-side-isolation-probes.md) §1、以及
[计划入口](../../docs/superpowers/plans/README.md)当时的措辞）：

> 完整包在 v237 根上余量只有 **11 s**……侧隔离通道是仓库既有的、已被官方裁决过 7 次的
> 定价口径：包更小、**余量充裕**，只测"该 Attention 机制本身值多少官方分"。
> 余量约 **57～62 s**——正是完整包缺的那个量级。

**这条推理错了，错在把"通道的属性"当成了"机制无关"。**

那 57～62 s 的余量不是侧隔离通道的固有性质，而是**此前被探针测过的每一个机制都很便宜**
的结果——v190/v191/v194/v195/v192 的侧隔离时间散在 234～272s，全都远低于 300s。
侧隔离包比完整包小，但**它同样有 300s 硬限**，而 Attention 的成本是跟着机制走的。
一个贵到能撑爆完整包的机制，同样能撑爆侧隔离包——只是偏移量不同。

**推论（这条要写进以后的开卡判据）**：
**侧隔离的可用性由机制成本决定，不由通道决定。** 对便宜机制，侧隔离能给出干净的
Attention 定价（v195 的 `+21` 被侧隔离与完整包两个口径交叉验证过，1:1 转移）；
对贵机制，侧隔离**连分都拿不到**——时间墙伸进了诊断通道内部本身。

这与 [2026-09-09 侧隔离分登记](2026-09-09-standard-linear-attention-side-scores.md) §5
的结论"侧隔离只能测分，不能测时间"是同一条边界的**加强版**：侧隔离不仅能测分不能测时间，
**它连"测分"这件事都不是无条件成立的**。

## 4. 不能由此得出的结论（逐条写明）

- **不能推出 v241/v242 完整包进不进 300s。** 侧隔离时间对完整包**无预测力**
  （v194 侧 −4s / 完整 +5s；v190 侧 246s / 完整 TIMEOUT 双向反例）。本次是反方向
  （侧也超时），同样不构成对完整包秒数的推断。
- **不能推出 VK 族耗尽。** 关闭的只是 v241 这个**实现**（计划 §7：停止条件只作用于具体实现）。
  v242 是另一个实现（per-KV-group，4 核，本地 V API 成本 ÷5.7），本次**未回传**，
  不受本文结论约束。
- **不反推官方调用次数。** 超时不返回任何数字，`250` / `200` 两个数字在仓库内仍互相冲突、
  均非实测（见[完整包超时记录](2026-09-11-v241-v242-vk-official-timeout.md)）。
- **不推导本地→官方换算系数，不写本地秒数预测。**
- **侧隔离分不晋级、不与完整分相加或互推**（AGENTS §2）。本文没有产生任何可加的分数。

## 5. 与本地读数的一致性（仅陈述，不外推）

本地 shard0 上 V API 的实测成本：v241 `7.094s / 12 calls`（`0.591 s/次`）
对 v242 `1.100s / 12 calls`（`0.092 s/次`），比值约 **6.4×**
（[构建记录](2026-09-11-vk-side-isolation-probes.md) §4 已登记）。
**超时发生在成本高 6.4× 的那个粒度上，与本地读数方向一致。**
本地读数是 GPU，官方判题是鲲鹏 920B（CPU），**不据此换算官方秒数**。
