# Linear A@W 拟合族九连败归因分析（2026-09-09）

背景：用户问"直接拟合应该能达到很高精度，为什么连续失败，拟合与测试方法是不是有问题"。
证据：v197（官方 −776）+ 并行 session 的 AW1–AW9/v204–v212（全部 REJECTED，
其中 AW1–7、AW9 六 shard 与根逐位相同零翻码，AW8 真实翻码但 −0.0171 且 3.8× 成本）。
数据口径与官方一致（Qwen3.5-4B proxy-v2 全量校准数据，不拆 fit/select），排除"数据集过拟合"解释。

## 归因（按结构性排序）

1. **增益/additive 形态结构性自闭（AW1–7、AW9 零翻码的根因）。**
   拟合假设部署 `g·Q(Ŵ)`，但 HiF4 编码器实际部署 `Q(g·Ŵ)`：自适应 scale
   （E6M2 指数取整 + lv2/lv3 重算）把标量/分组增益吸收掉，重编码后的整数码不比父好——
   实测父 hard loss 14.93 vs 重编码 23.78（差 60%），门控诚实拒绝 → 逐位相同。
   这是编码器结构决定的，与拟合数据、拟合精度无关；该形态不要再做。
2. **直接整数格点优化（AW8）过拟合校准窗口且成本不可部署。**
   冻结 Q(A)、贪心逐行 4 码组更新：真实翻码但整体 −0.0171（3/53/0，holdout 方向为负），
   且 3.8× 校准成本。校准集上能赢的整数扰动在独立窗口上是亏的——这才是"过拟合"的真实位置：
   不是数据不代表官方，而是**无结构约束的逐码自由度**必然过拟合。
3. **Weight GPTQ 本质上已是 per-column A@W 拟合。**
   根编码器逐列在 Hessian 度量下最优 + 误差反馈，事后重拟合的残余空间本来就小；
   这解释了为什么"直接拟合"没有拿到直觉中的大幅增益。
4. **测试方法无罪。** 本地 proxy 正确捕获了全部两种失败模式（零翻码 / 负向翻码），
   与 v197 官方 −776 方向一致；本地与官方排序未在此族反转。

## 边界

- 关闭的是"增益/additive 重拟合"与"无结构逐码贪心"两种形态；
  不推广为"A@W 拟合族整体无效"（AGENTS.md §7 对 LC1/LC2 的既有边界不变）。
- 拟合若复活只剩一种形态：A/W 联合、低自由度（结构约束防过拟合）、直接在码空间优化、
  且校准成本可控。成本高、现有证据偏负，不主动注册。
- 21071 锚点的"A@W拟合+Q/K互逆scale学习"机制证据与上述不矛盾：锚点实现未知，
  其拟合形态未必是已证伪的增益形态。
