## 2. 已确认的结构性差距

### P0：外部 v2.6 的 X/W 联合残差补偿，本地没有对应机制

外部在 `hif4_calibration_and_quantize_weight` 完成普通权重量化和
`activation_state` 构造后，调用 `_joint_refine_weight_params`。它把校准激活固定
变换为：

```text
Xt = NVFP4(A) 经过已选的 d / permutation / block-S
Xq = 已冻结 activation_state 的 Q(A)
Wt = 变换后的浮点 W
Wq = 当前合法 Q(W)
R  = Xt Wt^T - Xq Wq^T
```

对每个 64-channel block 和每一行，外部枚举 E6M2 顶层 scale 的
`(-2,-1,+1,+2,+3)` 五个偏移，并由 `_solve_exact_hierarchy` 重新求解合法的
lv2/lv3/mant。候选的输出误差增量是

```text
ΔE = 2 a_b^T δ + δ^T G_b δ
a_b = Xq_b^T R,  G_b = Xq_b^T Xq_b,
δ   = Wq_old,b - Wq_candidate,b
```

只接受 `ΔE < 0` 的候选；每次更新后立即用该块增量更新 `R`，最多做 3 次
Gauss--Seidel sweep。外部变更日志给出的隔离数字是：6 个 Linear 算子、72/72
层全胜，Linear 均值约 `+0.0548`（约 `+0.055`），校准时间约增加 15s。这个
数字尚未在本仓库复现，但它是目前唯一与 `1596` 分差距同量级的结构候选。

当前 C66/C69 已有：

- 4/8/16 组二阶权重精修、CAT-64、宽层 FULL64 GPTQ；
- 静态 `A@W` Q(W) headroom/product selector；
- Gram-8/Gram-16 等激活路径。

这些都是局部重建或静态候选选择，**没有**把量化激活误差与权重误差的交叉项
放回同一个输出目标。因此“继续扩大 FULL64 coverage、offset 或 Gram-8 比例”
不能解释外部的主要优势；缺失的目标函数比缺失的网格更重要。

### P1：外部对下投影使用 H32/H64 block-S，并按最终量化器排名

外部 v2.1/v2.5 对 `out_features < in_features` 的 Linear（典型 FFN down
projection）允许 block-S 尺寸 `4/8/16/32/64`，并把候选评估接到最终 HiF4
量化器（offset、importance、refine）而非只用标准重建代理。变更日志报告 proj
额外约 `+0.015`（H32/H64）和约 `+0.008`（最终量化器排序）。

本地当前 block-S 族为 `4/8/16`，且 CAT-64 与静态产品选择已经改变了候选空间，
所以不能直接复制外部的数字；但 Qwen-30B 类宽 FFN 很可能让下投影成为高价值
测试点。这是 C70 之后的独立 C71 消融方向。

### P2：外部删掉的微优化不是当前主要差距

外部 v2.7 删除了 permutation-base 扩展、V head importance 和把覆盖目标从
`0.999` 降到 `0.99`，变更日志称这些项在其 v2.6 基线上收益接近 0 或略负。
本地 C66 恰好因覆盖目标 `1.0` 比 C63 增加 `+0.606397` 的五模型代理分；这说明
这些开关具有实现/数据集依赖性，不能把“外部删掉”误读成“本地必须删除”。它们
最多是后续的时间压缩项，不是追赶 1596 分的第一手段。

### P3：采样预算不同，但不是精度差距的直接证据

外部 `_LINEAR_WEIGHT_EVAL_ROWS=256`，本地 C66/C69 为 512（CAT W Gram 另有
1024/4096 宽度分流）。外部少采样可能解释其较低时间，但不能解释更高分；在没有
新版官方用例之前，不应为了模仿外部而把本地采样盲目降回 256。

## 3. 合规边界审计

联合补偿可以纳入本题规则，但实现必须保持以下数据流：

1. `activation_state` 在联合补偿前完整构造并冻结；
2. `Xq` 只能作为校准期的固定输入，用于选择合法静态 `weight_params`；
3. 联合补偿产生的 `R`、`Xq`、候选得分和接受掩码全部在函数返回前释放，不能写入
   `activation_state`；
4. `hif4_dynamic_quantize_activation` 的在线路径和六个 API 签名保持不变；
5. 不用模型名、官方分数或两条测试用例的标签写分支。形状自含的宽层优化可以保留，
   但不能针对某个隐藏 case 设置专门门限。

因此它属于“校准期 `A@W` 优化 Q(W)”而不是违规的“`A@W -> Q(A)`”。需要在 C70
中加入一条回归检查：联合补偿前后 `activation_state` 的 CPU 序列化字节完全一致，
而 `weight_params` 仍通过独立 HiF4 合法性校验。

## 4. Qwen-30B 特征对候选排序的影响

官方额外提供了两个测试用例；目前从样例统计特征判断，它们接近千问 30B。用例
文件和完整 shape 清单尚未进入仓库，因此下面是结构假设，不是对隐藏数据的硬编码：

- hidden/FFN 宽度显著大于本地 Qwen2.5-0.5B 代理，`out < in` 的 FFN down-proj
  应有更高的 Linear 权重占比；
- Q/K 与 KV 的宽度可能不同，GQA/RoPE 使 Attention 的小样本候选更容易过拟合；
- 大矩阵上普通逐行 MSE 的候选排序更不可靠，校准输出残差的跨 block 相关性更有
  价值；
- 这两个 case 更适合验证“宽层联合补偿 + proj H32/H64”，不适合继续微调
  Attention center 或增加固定 offset。

在用例文件可用前，使用形状压力矩阵做诊断：hidden `4096/5120/6144`、FFN
`out < in`、GQA（例如 Q:KV 为 `32:8` 或 `32:4`）以及 RoPE；只报告机制的
相对变化，不把 synthetic 分数换算成官方分数。

## 5. 已登记的优化顺序

| 候选 | 唯一变化 | 主要验证 | 接受条件 |
| --- | --- | --- | --- |
| C70 | 在 C69/C66 之后加入 64-block X/W 联合 Gauss--Seidel Q(W) refine | 两个官方用例 + Qwen-30B 形状压力矩阵；消融 1/3 sweep | 合规、HiF4 合法、非 finite 排除、官方 `<420s`；不设每层/每 fold 硬门 |
| C71 | 仅 proj 的 H32/H64 block-S，并按最终量化器排名 | 与 C70 配对比较 proj/非-proj 分项和时间 | 只保留真实平均收益，避免全层宽块过拟合 |
| C72 | 对 C70/C71 做向量化、分块和缓存优化 | 复测 250/200 总时间 | 只为压入 420s，不改变已验证目标 |

C70 的默认参数沿用外部已验证的低自由度设置：五个 weight offset、最多 3 次
Gauss--Seidel、最少 8 个 calibration token；`ΔE<0` 是局部数学接受条件，不能
再叠加“每 fold 必须正向”“每层必须超过固定百分比”等过严防御。首先在 C66/C69
上做开关 A/B，再决定是否提交官方评测。

## 6. 结论

当前本地最高分已经是 C66 的 `22557 / 217.2s`，但最高分仍未超过外部 `24153`。
外部实现最值得移植的不是删除几个小开关，而是 v2.6 的**校准期 X/W 联合输出
残差补偿**；它正好利用用户允许的 `A@W` 优化静态 Q(W)，且不需要改变在线
激活量化。Qwen-30B 类两个新增用例进一步提高了宽 FFN、GQA 和跨 block 相关性
验证的优先级。后续不再把主要预算投入局部 offset/coverage 微调，先完成 C70
并记录真实官方用例的分项收益。
