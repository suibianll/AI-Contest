# A-SD1 结果：sign 生成器**确实是退化的**，但**它不是 C76.4 的杠杆**（2026-09-11）

**结论先行：发现了一个真缺陷，改了它，面板不升反降（shard 0 `−0.000338`，6 正 6 负 0 零）。**
**候选未归档、未推送；根保持 v245。**

---

## 一、缺陷是真的（两条独立测量）

旋转候选搜索（`C76.4`，官方定价 **+84 分 / 6 秒**，全项目价值密度最高）的生成器是
`_attention_rotation_signs(kv_num_heads, head_dim, seed)`，循环为

```python
_ATTN_ROTATION_BLOCKS = (16, 32, 64)  ×  _ATTN_ROTATION_SEEDS = (0, 1, 2, 3)   # 12 个候选
```

**在该形状（kv_heads=4, head_dim=256，1024 个位置）上实测：**

| 量 | 读数 | 随机 ±1 应为 |
|---|---|---|
| seed 两两 Hamming | **0 / 0 / 1 / 0 / 1 / 1** | ~512 |
| 单 seed 内符号翻转数 / 1023 | **995** | ~511 |
| +1 占比 | 0.501 | 0.5 |

**12 个候选实际只有 3 个**（每 block 一个）。原因在同一行里：

```python
bits = (index * 1_103_515_245 + seed * 214_013 + 12_345).bitwise_and(1 << 30)
```

- **`1 << 30` 是单个二进制位、不是掩码**；
- 乘子 `1_103_515_245 = 2³⁰ + 28_223`，所以第 30 位**几乎每步翻转** → sign 是 ±1 **交替**；
- `seed * 214_013` 最大约 6e5，而第 30 位的位值是 1.07e9 —— 加它只在**千分之一**的位置改变该位
  → **四个 seed 是同一个候选**。

Linear 侧的 `_linear_block_signs`（`solution.py:4465`）用的是**同一个写法**，所以这是**系统性**的，
不是笔误。

## 二、修了它，面板不升反降

把混合步换成 splitmix64（同一形状实测：Hamming 两两 **509–528**、翻转 **508**、±1 各半 ——
即真正随机），**成本不变**（同样 12 次迭代）。

`evaluator/eval.py --attention-only --shards 0` 对 v245 根：

```
cases 12   delta_mean -0.000338   pos 6   neg 6   zero 0
decision: reject   blockers: ['attention: delta_mean=-0.000338 <= 0']
```

**候选 SHA `a9da2569…7494`，未归档。**

## 三、这否证了什么、保留了什么

**否证**：
- **"恢复 sign 多样性会提高 C76.4 的分数"** —— 面板 shard 0 明确为负。
- 因此**"12 个候选其实是 3 个"这个缺陷本身并没有在扣分**。

**保留（未否证、也未测试）**：
- 缺陷本身**依然成立**（Hamming 0 是实测，不是推断）。它意味着**设计意图的搜索多样性没有实现**，
  只是这一次替换成随机版本并未兑现收益。
- 交替 sign 可能就是**更适合 HiF4 块结构**的选择（±1 交替 × Hadamard = 一种特定的结构化变换），
  随机版本反而破坏了它与 4/8/64 分组的对齐。**这是一个可解释的负结果，不是噪声的必然。**

**对下一轮的意义**：C76.4 的杠杆在 **block size 的选择**，不在 sign。若要继续动 C76.4，
方向是候选**变换族**（例如更多 block 尺寸或不同正交族），而不是 sign 的随机性。

## 四、口径

- 面板 shard 0 **只有 12 例**，且本项目已多次实测「本地面板对官方无预测力」
  （VK `+0.0046` → 官方 `−307`；A-MC1 `+0.0149` → 官方 `−2`）。
  所以本次的 `−0.000338` **同样不能外推官方**；它只支持"本地方向不是正的"这一个有限结论。
- 未跑六片全量（负结果，按纪律不推进）。
