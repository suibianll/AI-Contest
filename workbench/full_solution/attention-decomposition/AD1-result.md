# AD-1：Attention 误差分解，**第一次在计分口径下测出来**（2026-09-11）

**这是本项目第一个可信的 Attention 误差分解。它同时纠正了一条记反了的旧结论。**

---

## 为什么此前没有

面板把 `error_source_decomposition` 写死为 `False`（`proxy_v3_eval.py:570`），所以
**所有面板 artifact 都不含 Q/K/V 分解**；`official_eval.py` 的整包路径在这个 pack 上
跑不动（Linear-only 层的 qkv 槽为 `None`）。而曾经被引用过的两个"分解数字"
（0.7862 / 0.2194）实际是 `gain_qk_only` 与 `qk_interaction_gain`，**与 V 无关**（缺陷 #36）。

本卡**照抄**评测器的评分循环（`proxy_v3_eval.py:421-470`，缺陷 #19 的纪律），
补上评测器自己定义的两个臂（`official_eval.py:1719-1728`）：

```
reference  attn(q_ref, k_ref, v_ref)
standard   attn(q_std, k_std, v_std)     ← 分母
player     attn(q_hat, k_hat, v_hat)     ← 分子
v_only     attn(q_std, k_std, v_hat)     gain_v_only  = (e_std − e_v_only)/e_std
qk_only    attn(q_hat, k_hat, v_std)     gain_qk_only = (e_std − e_qk_only)/e_std
```

## 三条结论

**1. Q/K 贡献了玩家增益的 86%，V 只有 12%。**

`0.4603 / 0.5340 = 86.2%`；`0.0645 / 0.5340 = 12.1%`。
两者近似可加（0.4603 + 0.0645 = 0.5248 ≈ 0.5340），说明**Q/K 与 V 的贡献基本独立**。

**这一条把我此前写过的"V 占 78%"彻底推翻 —— 不只是无出处，而是方向相反。**
（那条已于本轮撤回，见缺陷 #36。）

**它同时解释了 VK（v241/v242）为什么弱、为什么官方 `−307`**：V 侧总共只有 `+0.065` 的
空间，而 VK 想用位置核去代替 `A` 去做 V 码选择 —— **在只有 12% 份额的那一侧做一件
需要跨 API 信息的事**。

**2. Q 与 K 只有在成对时才有意义。**

`gain_q_only = −36.0`、`gain_k_only = −36.1`：把其中一个换成标准编解码器，
输出误差**暴涨 36 倍**。原因是成对结构：`q_state` 与 `k_state` 共享
`learned_rotation`，Q 侧施加 `R` 就必须在 K 侧施加 `R^{−T}`；只动一边等于破坏配对。

**所以"分别优化 Q"和"分别优化 K"这两条路在结构上不存在**，任何 Q/K 机制都必须
**同时**编译两侧。这解释了为什么历史上所有可用的 Q/K 机制都是成对的
（v192 的 `Q@exp(S)` / `K@exp(−S)`、A-GR1 的 `Q@M` / `K@M^{−T}`、C76.4 的共享 sign）。

**3. 要补上 0.266 的缺口，Q/K 侧要再涨约 0.27。**

若 V 保持 `+0.065`，则 Q/K 需要从 `0.460` 涨到约 `0.735`（**+60%**）。
已知的 Q/K 机制量级是 `+0.004 / 个`（本地面板），所以这不是"再堆几个机制"能到的
——但这**不再是"不知道缺口在哪"**，而是"知道在 Q/K、且知道它需要量级上的变化"。

## 口径

- 本卡**不产生分数**，只产生定位。它不改任何候选、不发货。
- 读数为本地 GPU；但**分解是比值**（同一台机器上的分子分母），
  不涉及秒数、不外推官方。
- 与面板 `gain` 的完全一致是本卡最强的自检：**我的评分循环复刻了评测器**。
