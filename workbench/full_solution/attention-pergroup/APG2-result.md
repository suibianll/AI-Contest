# A-PG2：逐 KV 组旋转择优（APG-1 的落地实现）——本地负向，方向关闭（2026-09-19）

**结论：APG-1 提出的"逐 KV 组择优"已按两条设计实现并各跑一次完整六 shard Attention 面板；
两条都是本地负向（总体 `−0.0041`），且负向集中在层 8（`−0.0255`，9/12 case 变差）。
本卡的收益预测（`+0.004 ~ +0.006`）**未兑现**；按仓库纪律归档为负结果，不提交官方。**

---

## 1. 机制与实现

候选：`workbench/full_solution/attention-pergroup/candidate_apg2/solution.py`
（父 = 工作区 `solution.py` = v250，SHA `B1726CD9…`；候选只追加，父路径逐字节保留）。

目标是 **C76.4 旋转搜索**（`_ATTN_ROTATION_BLOCKS=(16,32,64)`；官方定价 +84 的机制）。
APG-1 的探针测的是这条链，不是 `_ATTN_BLOCK_SMOOTH_SIZES`（那条是 C86 块平滑，另有其链）。
本卡开工前先核对了 v205 的官方减法读数（关掉 `_ATTN_ROTATION_ENABLED` → `17969`，−84 分），
确认"旋转链在官方隐藏层上确实部署，只是本地 5 个校准窗上从不获胜"。

实现要点（一个机制、一个固定配置）：

1. `_attention_deployed_mse_grouped`：同一批前向，额外返回**逐窗口逐 KV 组**的 causal/safety
   误差。评分张量是 `(tokens, q_heads*head_dim)` 的逐元素均值，**逐 head 精确可加**，故逐组
   分解是恒等式；scalar 列表与父函数用同一 `.mean()` 归约（逐位相同）。**不新增任何前向**。
2. C76.4 候选循环：同一候选集合，逐组记录"该组自身窗口通过无退化门（`min_improvement=0.0`、
   窗口容忍 `_A1_GATE_WORST_TOLERANCE`、safety 容忍 `0.0`）且该组均值严格改善"的候选。
3. 组装：每个入选组携带**自己的 signs 行与 block**，其余组保持恒等（block 0）；
   `_apply_attention_rotation` 新增逐组 block 分支（int 路径逐字节不变），
   `_build_qk_states` 的 `rotation_block` 支持 list（int 路径不变）。
4. **复合态先验证再替换**：组装后的 state 用同一 grouped 评估过一次，要求逐组不劣于 base
   且逐组不劣于层级 winner；否则回退。机制上复合不可能劣于父机制（证明见 §4）。
5. 关闭开关 `_ATTN_ROTATION_PER_GROUP`：置 False 时**父路径零改动**。

两条设计（都测了）：

| 变体 | 逐组跟踪范围 | 效果 |
|---|---|---|
| 激进 | 全部 6 个候选 | 层 0/1/5/22 逐组门全拒（无可达变化）；层 8/15/22 变更 |
| **保守**（落档） | 只跟踪**通过层级门**的候选（3 个） | 层 0/1/5/22 无变化；层 8/15 变更 |

两个变体在层 8/15 选出的复合**完全相同**（`[0,64,0,64]` / `[0,0,32,32]`），
即激进版多出来的层 22（1 组）在保守版中被正确挡住。两版总体分别为
`−0.004089`（激进）与 `−0.004196`（保守），差 `= 层22 的 +0.000646/6`。

## 2. 等价性与可达性（先于任何面板读数）

- **control（per-group off）逐字节等于父**：六个 attention 层 q/k/v state 全字段比对，
  `IDENTICAL`（`apg2-states*.out`）。即关闭机制**没有任何副作用**。
- **可达性**：层 8 与层 15 各 2 个组入选，`rotation_block` 变为 `[0,64,0,64]` / `[0,0,32,32]`；
  层 0/1/5/22 逐组门拒收（不是 no-op，是门真的拒了）。
- **合法 state**：评测器 `validate_state` 六个层 3/3 通过；动态 q/k/v 五字段 finite。
- **部署路径**：逐组 block 经 `hif4_dynamic_quantize_q/k` 在真实数据上跑通、finite。

## 4. 为什么这不是实现错误

- 复合的逐组误差在组装时**实测复核过**（同一次 grouped 评估），并逐组要求不劣于 base
  与层级 winner；所以负向**不是**复合与单个候选不等价造成的。
- 复合不可能劣于父机制（数学）：层级 winner 通过层级门 ⇒ 除"严格改善"外的逐组检查它都满足；
  若某组均值未严格优于 base，则该组复合取 ≤base ≤ winner；否则 winner 在该组的候选集中，
  复合取 min。故**每一组上复合 ≤ winner**。负向只能来自"校准窗 ≠ 计分窗"。
- control 逐字节等价 + 关闭机制零变化，排除了审计键等副产物。

## 5. 与 APG-1 预测的差异（本卡的实质增量）

APG-1 的 `+0.004 ~ +0.006` 预测建立在"逐组 argmin 的**绝对** MSE 改善"上，没有过门、
也没有 held-out。本卡实测：

1. **严格逐组门在 4/6 层上拒收全部候选**（层 0/1/5 全拒；层 22 仅在激进版有 1 组）；
2. 在能过的两层（8/15）上，逐组选择的校准窗改善**不迁移**到计分窗。

所以 APG-1 的预测不是"差一点没兑现"，而是**在真实门与 held-out 下不成立**。
按 §7 停止条件，关闭的是**这个具体机制**（逐组择优 + 该门配置）及其两个已测跟踪范围；
不推广为"逐组分解无用"（分解是恒等式）或"旋转链不能再动"。

## 6. 保留的可复用事实

- 逐 head/逐 KV 组 MSE 分解是**恒等式**，且 `_attention_deployed_mse_grouped` 的 scalar 输出
  与父函数逐位相同；后续任何 Attention 侧逐组诊断可直接复用该助手。
- **C76.4 旋转链在本地 6 层中的 2 层（8/15）会真实被层级门接受**——更正"本地从不选旋转"
  的说法：那是**只看过层 0**（v205 的 verify）留下的印象。层 5 被 shard 映射到 shard5、
  层 22 到 shard4（六 shard 顺序为 `[0,1,8,15,22,5]`），面板逐层聚合后可以看到。
- **教训（与方法论同族）**：5 个校准窗上"逐组严格改善+窗口容忍"仍不足以约束 held-out；
  逐组自由度把过拟合从层级放大到组级。后续 Attention 侧机制若引入逐 head/逐组选择，
  须预期同样的迁移失败——除非选择规则本身不依赖校准窗排序。
