# LK-1 卡设计：为 `in_features = 9216` 的结构化编译度量（2026-09-11）

## 为什么做这张卡

- Linear 缺口的 **100% 集中在 fc_up / proj / fc_gate**（三者的权重都触及 9216 维 MLP 空间）。
- **`proj`（gain 0.4846，缺 0.32）被 L-EM2 排除**：`solution.py:11933 _EM1_MAX_CHANNELS = 4096`，
  `proj` 的 `in_features = 9216` → `em1_arm = "out-of-scope"`，其 `activation_state` 没有 `em1` 键。
- L-EM2 是**本项目唯一有官方收益记录、且本地读数可预测官方**的机制类别。
- 上限是**刻意的成本护栏**：度量要 `in×in` 的逆，9216³ ≈ 7.8e11 flops ≈ 12 s/层 × 24 层 ≈ 288 s，超 300 s。

**所以不是"取消上限"，而是"换一种存法"。**

## L-EM2 实际存了什么（读源码得到）

```python
gram   = Ŵᵀ Ŵ            # (in, in)
cross  = W_refᵀ Ŵ
h      = gram − cross      # -> state["em1"]["h"]，另外存标量 gram_diag_mean
```

注意注释里写明：存的是 `h` 而不是 `h_inv`；`h_inv` 在动态端构造。
即 **state 里带一个 `in×in` 的稠密矩阵**。

## 结构化近似：块对角

保留 `h` 的**按 64 块的对角块**（`in/64` 个 64×64 矩阵），丢掉块间项。

| | 全矩阵 (in=9216) | 块对角 |
|---|---|---|
| 存储 | 9216² × 4 B = **340 MB** | 144 × 64² × 4 B = **2.4 MB** |
| 动态求逆 | 9216³ = 7.8e11 flops | 144 × 64³ = **3.8e7 flops**（≈ 4 个数量级） |
| state 节点数 | 1 | 1（可存成一个 (144,64,64) 张量） |

块对角在**两个维度上都可接受**：存储降 140×，求逆降 20000×。

## 先决测量（**必须先做，再谈实现**）

**问题：块对角近似还剩下多少效力？**

在一个**全矩阵可用**的 role 上（如 `q`，in=2560）做对照实验：

```
臂 A  全 h 的下降到（现状）
臂 B  只用 h 的块对角部分的同一套下降
臂 C  父（不下降）
```

用**输出空间**的 `out_rel` 比较（本轮的坐标一致混合臂框架已验证可复现面板）。

判读：
- 若 B ≈ A → **块对角抓住了主要效力**，可以外推到 9216 给 `proj` 补机制。**这是 LK-1 的前置条件。**
- 若 B ≈ C → 块间项是效力来源，块对角无意义，LK-1 取消。

**这条测量便宜**（单 role、单层、单窗），且**它决定整张卡是否值得做**。

## 若先决测量通过，实现路径

1. `_em1_compile_metric` 增加一个块对角分支（`in_features > _EM1_MAX_CHANNELS` 时走它），
   或在 4096 以内就切到块对角（若 B≈A，全矩阵本来也没必要）。
2. `_em1_dynamic_descent` 的度量求逆改为按块。
3. 全新六 API 合同、合法 state、finite、可达性、未改侧 control。
4. 目标侧 4B shard0 → 六 shard。

## 诚实标注

- **本卡设计基于源码阅读，尚无任何实测。** 块对角是否保住效力**完全未知**。
- 若先决测量显示块对角无意义，**只关闭这个近似形式**，不关闭"给 proj 补机制"这个方向
  （还有低秩、分段、按 role 路由等其他结构化形式，均未测）。
- 不声称 `proj` 的 0.32 缺口能被这个机制补上——**L-EM2 在 4096 以内的 role 上贡献多少，
  我本轮也没有测过**。
