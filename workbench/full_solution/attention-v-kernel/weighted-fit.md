## 动机与为什么不成立

动机：现行拟合最小化 `Σ(A−W)²`，而规则最小化 `Σ_t‖(W−A)δ_t‖²`；两者只在残差 i.i.d. 时等价，
而 HiF4 块标度让残差强结构。所以应做加权 `w_b = Σ(‖δ_k‖²A)/Σ‖δ_k‖²`。

**不成立的原因（推断，未单独验证）**：`‖δ_k‖²` 集中在**大幅值**的 key 上，而这些元素往往是块内
已被块标度充分表示、**码不可动或动了收益很小**的。把拟合权重压到它们身上，等于让核在
**规则使不上力的地方**更准，而在能使上力的地方更钝。加权核与逐元素核的 max|gap| = 3.7e-2
（核量级 0.63），改动是实质性的，不是噪声。

## 一并记录的异常（未定位）

同一次运行里 `deployed vs replain max|gap| = 5.892e-01`——**候选 state 里实际使用的核，
与这里按同一定义重算的"逐元素桶均值"差 0.59，而核量级只有 0.63**。

两者按代码定义应当一致（同 radius、同 fit 窗、同 counts 归一化），**不一致说明有一处我还没看出来的差别**。
可能的方向：候选 `_vk_fit` 的行子采样（48 行散布）与本脚本（全行）在对**远桶**的估计上差别被放大；
或 `counts` 的累加条件。**在说清这一点之前，不应基于"核的拟合精度"继续推结论。**

## 与 ORACLE 测量的关系

ORACLE 说明**规则族的收益上限是 −8.82%**，现行核只兑现 −1.58%（约 18%）。
本卡否定的是**一条具体的提拟合精度的路线**，不是"精度是瓶颈"这个判断——
后者仍由 ORACLE 支撑，但**提精度的机制尚未找到**。
