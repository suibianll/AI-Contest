# A-JC1 参数方向检查：解析梯度与硬目标响应的比对

> 执行 `ajc1_hard_gradient.py` / `ajc1-hard-gradient.json`。2026-09-10。
> **合成 CPU 设定**（契约的 8 token、2Q/1KV head、hd64），**不是 4B 面板证据、不是裁决**。
> 目的：补上修订后报告 §4 要求、而此前从未做过的两项检查——**参数方向 `g_θ = J_θᵀr` 与实际硬码响应**。

## 1. 方法

- 复用契约的 `features` / `hard` / `attention`（直接 import `contract_smoke`，不改动它）；
- **解析方向**：契约已有 `g = Jᵀr/numel`（平滑松弛的雅可比）；
- **硬响应**：对 8 个参数逐个做中心差分，**穿过同一个 `hard()`**（即真正会部署的那个取整编码），
  在 θ=0 与求解所得 θ 两处各测一遍，δ 取 0.25/0.5/1.0/2.0。

## 2. 结果

| δ | θ=0 处硬 FD 范数 | 恰好为 0 的参数 | 与解析 g 的 cos | 求解点处硬 FD 范数 |
|---:|---:|---:|---:|---:|
| 0.25 | **0.000e+00** | **8/8** | +0.000 | 2.557e-03 |
| 0.5 | **0.000e+00** | **8/8** | +0.000 | 2.498e-03 |
| 1.0 | 1.297e-03 | 2/8 | +0.123 | 1.331e-03 |
| 2.0 | 2.176e-03 | 0/8 | **+0.845** | 1.078e-03 |

解析 `g` = `[-0.000207, -0.000614, -6.5e-05, -0.00016, 0.000353, -0.000623, -6.5e-05, -0.000141]`

硬 MSE：父（θ=0）`0.0044368474` → 求解点 `0.0045914480`（**差 3.48%**）。

## 3. 读数：这是**尺度**问题，方向大致是对的

**（a）硬目标在父点附近是平坦的。** δ ≤ 0.5 时八个参数的有限差分**全部恰好为 0**——
扰动 ±0.5 以内没有任何一个元素的 `phi@θ` 跨过 `round()` 的 0.5 阈值，因此**没有一个码被改动**，
硬 MSE 严格不变。求解器的步长正落在这个"不动区"里，于是它最小化的那个"梯度"在部署目标中并不存在。

**（b）方向并不矛盾。** 把 δ 放大到 2.0，硬 FD 与解析 `g` 的 **cos = +0.845**——
说明解析方向与硬目标的真实响应**是大致一致的**，问题不在方向。

**（c）但求解点仍然更差。** 硬目标是阶梯：θ 落点决定它踩在哪个台阶上。平滑模型假设"小步长 ⇒ 成比例的
小改善"，在取整编码下该假设不成立，所以求解出来的具体点反而劣于父点 3.48%。

## 4. 这支持什么、不支持什么

**支持**：
- 契约里"平滑 J 是松弛、不是硬导数"的自我说明**得到实测确认**，并给出了它的具体形态
  （θ≈0 附近宽度约 ±0.5 的平坦区）；
- 主线的**方向部分**（`J_θᵀr`）与硬响应在大步长下对齐（cos 0.845），**不是无效方向**；
- 失效点在**尺度/落点**：求解没有保证跨过一个码步、也没有在硬目标上做落点检查。

**不支持**：
- **不支持**"A-JC1 不可行"或任何阴性裁决——本检查只定位了一个**可修的实现问题**；
- 也**不支持**"加上尺度约束就能达标"——合成设定、单点、未测跨 0.5 之后的硬响应是否单调；
- 更不支持任何 4B/官方层的结论。
