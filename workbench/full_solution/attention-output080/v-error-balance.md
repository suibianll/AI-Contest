# V 误差平衡取整：真实码选择在面板上的结果（+0.0038，非天花板）

> `v_error_balance.py` / `v-error-balance.json`。2026-09-10。CPU、未训练、未跑 shard、未出候选。
> 目的：把 `v_common_mode.py` 测出的**机制天花板**（+0.0412）实现成**真实可部署的码选择**并验证。

## 机制与算法

目标为 attention 输出 MSE。`O = A·V` 且 A 行和恒为 1 ⇒ 误差的共同模态全额通过、振荡分量抵消。
可部署代理（只用 V 自己的码与输入）：**每通道令重建误差跨 token 之和趋零**。

算法：从父码出发，逐通道贪心做 ±1 `mant` 码步，选"最能把 Σδ 拉回零、operand 误差增加最少"的翻转，
最多 6 轮；`sign==0` 的零码冻结；尺度层级全部不动（与 A-JC1 同样的"refine 后只改 mant/sign"边界）。

## 结果（30 例，`MAX_TOKENS=256` 过滤）

| | 值 |
|---|---:|
| gain 现在 | 0.5214 |
| **gain 误差平衡** | **0.5252（+0.0038）** |
| 天花板（数值平移，72 例口径） | +0.0412 |
| 平均翻转码数/例 | 2960 |
| operand MSE | 0.01952 → **0.02368（+21%）** |

按层：0: +0.017、15: +0.027、8: +0.005，而 1: −0.015、5: −0.007、22: −0.004 —— **符号混杂**。

## 为什么天花板拿不到（差距的确切原因）

**粒度不匹配**：天花板是用**精确减去每通道均值**（连续量）算的；而码选择每次只能移动**一个码步**，
**码步比要抵消的均值粗**，均值清零不了。于是算法翻掉近 3000 个码去追一个追不上的量，
剩余残差以噪声为主，逐层符号因此翻转。

## 支持 / 不支持

**支持**：
- 该机制**可部署性成立**（只读 V 自己的输入与冻结尺度，满足"动态端只看自己输入 + 编译 state"）；
- 它确实在按预期交换——operand MSE 恶化 21% 而输出 gain 略升，方向与机制一致；
- **机制天花板（+0.0412）不可由"±1 码步贪心"取得**。

**不支持**：
- **不支持**"误差平衡这条路无效"——只否定了**这一版取整算法**（逐通道独立、无注意力加权、仅 ±1 步、6 轮）；
- **不支持**任何关于 0.80 的裁决；
- 30 例不是 72 例，且逐层符号混杂，+0.0038 本身很可能不显著。
