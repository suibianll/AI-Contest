# 闸门 0 结论：Q/K 子空间不可压缩 —— A-JC1 主线记 API_INCOMPATIBLE

> 计划 §3 第 0 项（第一道闸门）。执行：[`gate0_compressibility.py`](gate0_compressibility.py) / `gate0.json`。
> 2026-09-10。**未训练、未跑 shard**：每窗口一次前向 + 一次反向。

## 1. 闸门问的是什么（先把问题摆正）

计划的措辞是"需要本次完整 QK、softmax 或另一动态 API 输入才可选码"。这里要防一个**过度论断**：
目标函数在动态端不可评估，并**不**意味着规则不可执行——目标是**校准期**的对象，规则才是动态端执行的。
所以真正可判定的问题是：

> **"只看自己输入 + 编译 state"这类规则，能否表达出联合最优解中 Q（或 K）那一半的方向？**

## 2. 判据：Q/K API 自己到底能算什么

动态 API 签名（源码核过）：每个只拿自己的 `(quant, scale, heads, head_dim, state)`，没有跨 API 输入，
也不得利用调用顺序。所以 Q API 能构造的**只有**它自己的两个量：

- `Q_ref = dequantize_nvfp4(q_quant, q_scale)`（参考解码）
- `Q_hat`（部署解码）

因此它**能**评估的、与误差相关的量，最自然的就是自己的 operand 误差 `||Q_hat - Q_ref||²`。
判据因此是：**输出损失对 Q 的梯度 `g_Q`，与 Q 的 operand 误差梯度，方向对不对得上。**

## 3. 实测（真实窗口，四层各 12 窗）

| 层 | windows | loss | **cos(g_Q, Q自身)** | **cos(g_K, K自身)** | cos(g_V, V自身) |
|---|---:|---:|---:|---:|---:|
| 22 | 12 | 0.018992 | **+0.040** | **+0.030** | +0.523 |
| 15 | 12 | 0.002535 | **−0.010** | **−0.008** | +0.367 |
| 1 | 12 | 0.002291 | **+0.002** | **+0.001** | +0.288 |
| 0 | 12 | 0.000657 | **−0.017** | **−0.018** | +0.417 |

**Q/K 端四层全部 ≈ 0（正交）**；V 端 0.29–0.52（实质性对齐）。

## 4. 为什么必然如此（不只是经验）

链式法则直接给出：

```
O = softmax(Q K^T / sqrt(d)) V ，  L = ||O_hat - O_ref||²
∂L/∂Q_hat ∝ K_hat · (J_softmax^T e) / sqrt(d)        e 由 ∂L/∂O 与 V_hat 组成
```

即 **`g_Q` 住在 `K_hat` 的行空间里**（它是 `K_hat` 各行的一个加权组合）。而：

- `K_hat` 是**另一个 API 的输入**，Q API 看不到；
- Q 的 operand 误差 `Q_hat - Q_ref` 是 Q 自身量化误差，与 `K_hat` 的行空间基本不相关（不同的投影）。

**两个子空间不同 → 正交。** 实测的 ≈0 正是这条代数事实的数值确认，不是一次噪声。
对称地，`∂L/∂K_hat ∝ Q_hat · (...)`，K 的梯度住在 `Q_hat` 的行空间里，同样不可得。

**这条还说明：把"加权版 operand 误差"（编译一个固定权重 W）拿来救，也不成立。**
W 在校准期固定，而 `g_Q` 的方向逐窗口变化；一个固定 W 无法对齐一组逐窗正交于该子空间的方向。
要翻案，主线必须**证伪**上面这行链式法则的推论，而不是换一个 surrogate 再试。

## 5. 裁决

**A-JC1 主线（Q/K 联合输出残差驱动的校准规则）记 `API_INCOMPATIBLE`，停止该实现设计。**
按计划 §3："这样死的是结构、不是训练效果，代价只有一次合同审计。"——本次审计的全部成本是
一次 4 层 × 12 窗的前向+反向，没有训练、没有候选、没有 shard。

**这不是"训练没效果"，也不是"机制没价值"**：从展开点看，输出损失确实对 Q/K 的改变敏感
（梯度非零），只是**改变的方向由另一个 API 的输入组织**，在现行 API 合同下无法在动态端决定。

## 6. 测量顺带指出来的东西（只登记，不据此开卡）

同一批数据里，**输出损失的梯度与 V 的 operand 误差对齐 0.29–0.52，与 Q/K 对齐 ≈0**。
这也是结构性的：`O = P @ V`，V 的误差经 softmax 权重线性通过（权重和恒为 1），
而 Q/K 的误差要穿过 softmax 的饱和非线性。

**含义**：如果要从"降低 operand 误差"这条路上拿分，**V 是唯一在输出损失里站得住的那一侧**。
但本计划 §2 明写"V量化器保持不变"，AGENTS §3 也把"V 码分配"列为已关闭方向。

**因此本文件只登记这个读数，不据此开卡**：它是一次**有数据支撑的方向提示**，
若要走，需要先取得对该关闭方向的明确授权，并按 AGENTS 对"重开已关闭机制"的要求
说明与旧实现（含 A 系列、C76.4）的实质差异。**在授权之前，不做任何 V 侧实现设计。**

按 §5 备选的前置条件（"只在主线合同/开发有明确结论后执行"），**该结论现在已给出**：
