# 三方分解：+0.0038 的差距在**代理**，不在搜索（也不在"粒度"）

> `v_proxy_diagnosis.py` / `v-proxy-diagnosis.json`。2026-09-10。CPU、未训练、未跑 shard、未出候选。

## 要分开的三件事

`v_error_balance.py` 报 +0.0038（天花板 +0.0412），我当时归因为"码步粒度"——**那是过度归因**。
同一批 30 例上，前后各测三个量：

| 量 | 前 | 后 | 变化 |
|---|---:|---:|---:|
| **PROXY** `(Σ_k δ_c)²`（V 自己能算） | 5367.56 | 1186.82 | **−77.89%** |
| **TRUE** `‖A δ_c‖²`（真实输出量，A 为父注意力概率、含因果掩码、按 GQA 分组） | 2071.94 | 2125.81 | **+2.60%** |
| OPERAND mse | 0.01952 | 0.02368 | +21.32% |

逐例：**代理改善 30/30；真实量改善仅 10/30**。

## 裁决

**搜索不是瓶颈**（代理被压下 78%）；**代理是瓶颈**（压 78% 而真实量升 2.6%）。

> 只有 V 自己能算的那个无权重代理，与真实量 `‖Aδ‖` 之间**不是近似关系，而是接近无关**。

**结构原因**：真实量是 **A 加权**的（逐通道 `‖A δ_c‖`，且 `‖Aδ‖²_F = Σ_c ‖Aδ_c‖²` 可分，
所以逐通道处理本身没错），而 **A 是 Q/K 侧、输入相关的量，V 的动态 API 拿不到**。
可部署的代理只能退化成无权重版本，于是与真实量脱钩。

## 这否定什么、不否定什么

**否定**：
- **"每通道令 Σδ 趋零"这一条**作为通向天花板的路径——它可部署，但与目标脱钩；
- 我上一轮"差距源于码步粒度"的归因（正确原因是代理选择，非搜索强度、非粒度）。

**不否定**：
- 天花板本身（+0.0412，用真实 A 减精确均值测得）——它仍是**该机制的天花板**，
  只是**通往它的路必须知道 A**；
- 任何关于 0.80 的裁决；
- 也不支持"V 侧无路"——只说明**这一条代理**不行。

## 与前面墙的关系

这是同一堵墙的第三次出现：**输出结构需要跨 API 的信息**。Q/K 主线（`g_Q` 需要 `K_hat`）、
V 的可部署代理（需要 A）、A-JC1（`deltaA` 需要 V 与另一侧）——三者受阻于同一处。

**但注意区别**：前两次我据此下了近似裁决并撤回；**这一次是一个干净的实测**（30/30 vs 10/30
的逐例方向），可以支撑"**这条代理不是通往天花板的路径**"这个**有限**结论。
它不支撑任何"整条路已死"的结论。
