# V 卡前审计：天花板是真的，但可动的杠杆比预期窄

> 授权：2026-09-10 用户明确授权校准期 V 码分配（AGENTS §3 带日期例外条款）。解码格式、五字段、
> 动态无搜索约束不变。
> 测量：[`ceiling_decomposition.py`](ceiling_decomposition.py)、[`v_room_audit.py`](v_room_audit.py)、
> [`v_headroom_probe.py`](v_headroom_probe.py)。**全程 CPU，未训练、未跑 shard、未出候选。**

## 1. 为什么值得开（已测）

| 反事实（72 例） | gain |
|---|---:|
| 现在 | 0.5340 |
| **V 完美** | **0.8115（≥0.80）** |
| Q 与 K 同时完美 | 0.7204（<0.80） |

V 是达到 0.80 的**唯一**通路。层 22 现在 0.3015，单靠 V 就能到 0.9634。

## 2. 当前 V 校准几乎没买到东西（已测）

| | E_current | E_standard | |
|---|---:|---:|---|
| **V** | **0.018454** | 0.021210 | 校准只比未校准好 **13%** |
| Q / K | — | — | **列不可读**：Q/K 带 gauge（学到的 rotation），拿旋转后的 Q_hat 比未旋转的参考会得到 200× 假误差 |

所以：**V 有 87% 的标准编解码误差原封不动地留着**，而它正是输出误差的主项。

## 3. 细化预算旋钮是死的（已测，这是本审计最重要的一条）

把 V 的 `max_refine_ratio` ×2 / ×5、`max_refine_blocks` ×4、两者同时放大，**五项变体的 gain 与 E_v
六位小数完全相同**（0.5340 / 0.018454，逐层也完全相同）。

**读法**：V 的码在现有偏移窗口 `(-1,1,2,3,4)` 下已到**局部最优**——多给预算，没有更好的码可选。
**因此"提高 V 的求细化强度"不是杠杆，做了也是 0。** 这一条必须写进卡里，否则后续会重复试它。

## 4. V 在代码里到底能被动什么（源码核对）

`_build_v_state` 的六个字段，来源如下：

| 字段 | 现在怎么来 | 是否可动 |
|---|---|---|
| `importance` | **attention mass**（`v_head_mass` 归一化） | ✓ 已是输出感知的权重 |
| `max_refine_ratio` | `_loss_capture_ratio(importance 加权的 operand 块损失, target=1.0)` | ✗ §3 已证其变化无响应 |
| `max_refine_blocks` | 常量 24576 | ✗ 同上 |
| `search_offsets` | 常量 `(-1,1,2,3,4)` | 是 state 字段，**可动**（但见 §5） |
| `error_threshold` / `accept_margin` | 常量 | 只用于拒绝细化（§5 说明其作用） |

并且：`_dense_to_hif4` 里 **gram 驱动的 `_adaround_mantissa` 路径对动态 Q/K/V 全部不走**
（三个动态 API 都不传 `group_gram`）；V 走的是"importance 加权的 operand 误差"细化路径。

## 5. 于是可动的只剩一条：**判据本身**

V 的码由 `_dense_to_hif4` 内部挑选，判据是 **importance 加权的 operand 误差**：

```
weighted_error = (x_abs - mantissa·denominator)² · importance
normalized_error = weighted_error.sum(块内) / energy.sum(块内)
→ 按 normalized_error 排序，取前 refine_ratio 比例的块做偏移搜索
```

而**输出误差**对 V 的依赖是 `||P (V_hat − V_ref)||²`（P 是注意力概率，softmax 权重和为 1）。
两者**不同**：前者把每个元素按 importance 加权后**平方再求和**，后者是**先对块内元素求和、再平方**
（经 P 加权）。前者只关心"这个元素自己错多少"，后者关心"这些元素合起来在输出里错多少"——
**块内的误差可能相互抵消**。

**这就是本卡要动的唯一一处**：把 V 的码选择判据从"importance 加权的 operand 误差"换成
"经注意力概率加权的输出误差"。这是一个**判据替换**（固定、单一、不扫描），不是加预算、
不是扫参数、不改格式、不改动态端。

## 6. 尚需在卡内先回答的两个问题（不预设结论）

1. **判据是否可校准编译**：输出判据里的 P（注意力概率）随输入变化，动态 V API 看不到 Q/K。
   但——与闸门 0 的主线不同——V 侧的**码选择发生在动态端**（`_dense_to_hif4` 在动态调用里跑）。
   所以问题是：判据若必须在动态端用 P，就违反"动态无跨 API 输入"。**必须先把判据写成
   "只依赖 V 自己的输入 + 编译 state"的形式**，否则同样记 `API_INCOMPATIBLE`。
   可行的方向是在校准期把 P 的统计以合法字段（如逐 head/块的权重）编进 `v_state`，动态端只用
   该权重——**但这需要先证明该压缩成立**（同闸门 0 的方法：测方向对齐度）。
2. **可达量级**：即使判据替换成功，能拿回多少？§3 的局部最优性提示 V 的码在当前**窗口**内已最优，
   换判据可能只改变**哪些块被细化**，而不是每个块内的码。故本卡的可达上界**低于** 0.8115，
   实际增量由第 1 步的测量决定。

## 7. 建议的固定配置（待第 6 步通过后预注册）

- **一个**判据替换：V 块内码选择由 importance 加权 operand 误差 → 输出（P）加权误差，
  P 的压缩形式由第 6.1 步的测量决定并固定；
- 其余全部不变：`importance` 仍取 attention mass、offsets/threshold/accept_margin/blocks/ratio 全不动、
  编解码格式与五字段不动、动态不新增搜索循环与跨 API 输入；
- **不扫描**上述任何参数；不重开 A-GR2 学习率/归一化/步数邻域。

## 8. 本审计的边界

- 全程未训练、未出候选；§3 的"旋钮无效"是在**未改动任何代码**的前提下、用现有 `v_state` 直算的。
- §5/§6 的判据替换**尚未实现、尚未测量**；本文件不预言它能带来多少 gain，也不预言 0.80 可达。
- 唯一已经确定的是：**不换判据、只加预算 = 0**。
