## 3. 保留的测量读数，以及每一项"不支持什么"

### 3.1 operand 反事实读数（`ceiling_decomposition.py` / `ceiling.json`）

把某个 operand 换成它的无损参考解码、其余不变，重算 72 例面板：

| 反事实 | gain |
|---|---:|
| 现状 | 0.5340 |
| 只把 V 换成参考（Q/K 不变） | 0.8115 |
| 把 Q 与 K 同时换成参考（V 不变） | 0.7204 |

**⚠ 这不是上界。** 见 §5.1：Q/K 的作用是让最终输出接近参考，**不是**接近参考 Q/K 本身；
固定量化 V 时改变注意力概率可以补偿 V 的误差（用户的代数反例）。
所以这两行只能读作"在这两种特定替换下的读数"，**不能**读作"某一侧的最好结果"。

（另一处记录保留：单独替换 Q 或 K 会得到 −36 量级，那是**无效反事实**——Q/K 带 gauge，
单独换一个会破坏 `Q@Kᵀ` 的乘积，只有同时替换才一致。）

### 3.2 一种 operand 梯度与输出梯度的对齐度（`gate0_corrected.py` / `gate0-corrected.json`）

真实窗口、四层各 12 窗，比较 `g_Q = ∂L/∂Q_hat` 与 Q 在**部署 gauge 内**的 operand 误差梯度：

| 层 | cos（Q） | cos（K） |
|---:|---:|---:|
| 22 | +0.042 | +0.031 |
| 15 | −0.012 | −0.008 |
| 1 | +0.003 | +0.003 |
| 0 | −0.017 | −0.021 |

**支持的**：在这四层的当前点上，**这一种** operand 误差方向对输出目标的改善很弱。
**不支持的**：不能否定"其他输入条件化规则"；也不能推出 API 不兼容。
初版写的"代数必然/换 surrogate 也救不了"**撤回**——`g_Q ∝ K_hat·(Jᵀe)/√d` 只说明 `g_Q`
落在 `K_hat` 的行空间里，而 **K 满列秩时该空间即整个通道空间**，正交性是当前点的性质、不是必然。

### 3.3 V 侧的 operand 优化空间（三个脚本，均为 **operand MSE** 判据）

| 层 | 检查 | 结果 | 覆盖 |
|---|---|---|---|
| 元素级 `sign`×`mant` | 固定当前尺度下的每元素最优档（float64） | 与现状**误差相同**；被"改动"的 1.3–2.1% 元素是**等距并列** | 元胞级 = 完整 |
| 块尺度 `scale_factor` | 9 档**整 case 统一倍率**取均值最优 | **×1.0 在 36/36 case 最优** | **弱**：不是逐块选择，不是 E6M2 全空间穷举，只 3 层 |
| 层级 `lv2`/`lv3` | 逐 8 元素组穷举 8 种组合（合法 oracle） | operand 误差 0.0184536634 → 0.0184532213 | 逐组 = 完整（operand 判据） |

**⚠ 这三项都是对 `||ΔV||²` 的优化，不是对 `||AΔV||²` 的优化。** 见 §5.3。
且块尺度一项**明显超过实际测试覆盖**（初版把它写成"每一层、每一级都最优"，撤回）。
数值呈现也更正：0.0184536634 → 0.0184532213 是约 **0.0024%** 改善，不是"0.00%"意义上的零。

**一个仍然成立的线索**：合法 oracle 找到一个 operand 误差相同、gain 低 2.15% 的编码
（0.5340 → 0.5225）。这**恰恰说明**"operand 等价 ≠ 输出等价"，因此 operand 判据下的最优
**不能**升级为输出最优——它是这次修订里最关键的一条证据。

### 3.4 其他已核对的事实（不受修订影响）

- **`importance` 对 V 不起作用**：实测 `importance=None` 与现状**逐位相同**；
  它在 `normalized_error = Σ(err²·w)/Σ(x²·w)` 中分子分母同为逐通道常数而约掉。
- **refine 是活的但预算已用满**：`max_refine_ratio` 经 `_loss_capture_ratio(target=1.0)` 本就是 1.0；
  `max_refine_blocks` 24676 未触顶；关掉 refine 会差 16.6%。
- **`_build_v_state` 的六个字段**中只有 `importance` 是数据驱动的，其余为常量或 operand 级启发式。

## 4. A-JC1 主线：接口可实现性**未被证否**，应继续检查

初版以闸门 0 的单一 surrogate 正交性裁定 `API_INCOMPATIBLE`，**撤回**。

**真正需要检查而尚未检查的**：

1. **参数方向** `g_θ = J_θᵀ r`——对规则**参数**（而非对 `Q_hat`）的梯度；
2. **编译规则产生的实际硬码变化**——规则跑出来后 `sign`/`mant` 实际改了哪些、方向是否与 `g_θ` 一致；
3. **可达性**——规则编译后在 72 例上是否真的改变了硬输出（而不是全退回原码）。

在这三项有结果之前，**不能**对该主线作任何否定裁决。

## 5. 已撤回的裁决与原因（本报告初版的六个缺陷）

### 5.1 把"替换为无损输入"当成优化上界

用户的代数反例（说明逻辑错误，非本题合法候选）：参考概率 `[0.5,0.5]`、参考 V `[0,1]` → 输出 `0.5`；
量化 V `[0.25,1.25]` 用参考概率 → `0.75`；**把概率改为 `[0.75,0.25]` → 输出恢复 `0.5`**。
即 **Q/K 更接近参考并不保证最终输出更好**，反过来**变化的 Q/K 可以补偿 V 的误差**。
故 `0.7204` 不能证明 Q/K 无法达到 0.80，`0.8115` 也不能证明 V 是唯一通路。

### 5.2 梯度近乎正交不能推出 API 不兼容

只比了一种 surrogate；"梯度位于 K 的行空间"不意味着与 Q 误差正交（K 满列秩时该空间即全空间）。
应检查参数方向与实际硬码变化（§4）。

### 5.3 operand 最优被错误升级为 Attention 输出最优

固定概率矩阵 `A` 时：operand 误差 `||ΔV||_F²`，输出误差 `||A ΔV||_F²`——**两个不同目标**。
逐元素最近舍入、固定尺度下的层级穷举，即使确为前者最优，也**不能**证明后者最优。
本报告 §3.3 的 tie 证据（operand 相同、输出不同）正是这一推导不成立的反证。

### 5.4 scale 脚本并未做逐块全空间最优

`v_scale_headroom.py` 先对**整个 case** 求 `err.mean()` 再选一个倍率，测的是
"9 种**整 case 统一倍率**中哪个平均误差最低"，**不是**逐块独立选择，**更不是**穷举全部合法 E6M2 尺度；
且只跑了 3 层，却被初版推广成"每一层、每一级都最优"。**结论超过测试覆盖。**

### 5.5 "未训练、复用现有 state"与代码不符

多个脚本直接调用 `solution.hif4_calibration_attention(...)` **重新生成 state**，
而当前根的校准函数**包含训练**（A2 rotation 训练等），因此"没有训练"的表述不实。
且这些脚本经兼容后端直接计算，**未绑定源码 SHA、校准 state 与逐 case 一致性**；
均值四舍五入相同**不能**证明与已有 eval-v3 基线同口径。

### 5.6 "改解码格式只需授权"不成立

《赛事说明书》§2.4 的"对其他数据结构、函数接口及实现不作限制"约束的是**编码算法可自由设计**，
**不代表**官方解码器会随之改变。**用户授权也不能改变判题器接口。**
同理，"换指标"没有依据——不可达尚未被证明，**0.80 目标与原评测口径保留**。

**本轮共改正十一处自身缺陷**——这是报告的一部分，不是附注。

| **6** | **把"替换为无损输入"当优化上界** | **用户审读（代数反例）** |
| **7** | **用一种 surrogate 的正交推 API 不兼容** | **用户审读** |
| **8** | **operand 最优升级为输出最优** | **用户审读** |
| **9** | **scale 脚本非逐块、非穷举、3 层却推广** | **用户审读** |
| **10** | **"未训练"与代码不符；未绑定 SHA/同口径** | **用户审读** |
| **11** | **把"实现不受限"扩展成"可改解码语义"** | **用户审读** |

**方法论结论（修订）**：前五处由**独立实现交叉比对**抓出，后六处**全部由用户审读抓出**——
其中第 6、8 两条是**逻辑错误**，我的自我交叉验证机制对逻辑错误**完全无效**
（两份脚本可以共享同一个错误前提并自洽）。这条比任何单个结论都重要。
