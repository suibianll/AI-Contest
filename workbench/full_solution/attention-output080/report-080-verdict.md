## 3. 三条线的界

### 3.1 Q/K 联合输出残差主线（A-JC1）—— `API_INCOMPATIBLE`

**设计**：用完整部署输出误差 `||r + J_softmax(Z0)[δZ]V0||²` 指导一个可校准编译的 Q/K 舍入规则，
其中 `δZ = (δQ·K0ᵀ + Q0·δKᵀ + δQ·δKᵀ)/√d`。

**闸门 0 的问题**：目标函数在动态端不可评估并不构成障碍（目标是校准期对象）；
可判定的是"**只看自己输入 + 编译 state 的规则，能否表达联合最优解中 Q/K 那一半的方向**"。

**测量**（真实窗口，四层各 12 窗，每窗一次前向+一次反向）：

| 层 | cos(g_Q, Q 的部署 gauge 内 operand 误差梯度) | cos(g_K, 同) |
|---:|---:|---:|
| 22 | +0.042 | +0.031 |
| 15 | −0.012 | −0.008 |
| 1 | +0.003 | +0.003 |
| 0 | −0.017 | −0.021 |

**四层全部正交**。且这是代数必然，不是噪声：

```
∂L/∂Q_hat ∝ K_hat · (J_softmaxᵀ e) / √d      → g_Q 住在 K_hat 的行空间里
```

而 `K_hat` 是**另一个 API 的输入**；Q 自身的量化误差与该子空间基本不相关，故正交。
对称地，`g_K` 住在 `Q_hat` 的行空间里。**换一个加权 surrogate 也救不了**：
权重在校准期固定，无法对齐逐窗变化、且逐窗正交于该子空间的方向。

**裁决**：记 `API_INCOMPATIBLE`，停止该实现设计。审计成本仅一次前向+反向。

### 3.2 V 侧——逐层已最优，残差是表示法的

V 是通向 0.80 的**唯一**通路（V 无损 → 0.8115；Q/K 无损 → 0.7204）。但把 V 的**每一层自由度**查完后：

| 层级 | 自由度 | 结局 | 判据 |
|---|---|---|---|
| 元素级 | `sign` × `mant`（8 档） | **已最优** | float64 oracle 改进 **0.000000%**（层 22/15/0）；"被改动的 1.3–2.1% 元素"实为**等距并列** |
| 块级 | `scale_factor` | **已最优** | 9 档倍率（2⁻²–2²）oracle 中 **×1.0 在 36/36 case 全胜**、headroom 0.0000%（amax 设定双向饱和） |
| 层级 | `lv2`（每 8 元素组一位）、`lv3`（每 4 元素对一位） | **已最优** | 合法 oracle（**逐组**穷举 8 种组合）operand 误差 **0.00%**（0.0184536634 → 0.0184532213） |

另外两条实测支持"残差不在这条路上"：

- **`importance` 完全不起作用**：它在 `normalized_error = Σ(err²·w)/Σ(x²·w)` 里分子分母同为
  逐通道常数而**直接约掉**（`importance` 为逐 head 常数展开，64 通道的块不跨 head）；
  实测 `importance=None` 与现状**逐位相同**。
- **refine 是活的但已用满**：`max_refine_ratio` 经 `_loss_capture_ratio(target=1.0)` 算出**本就是 1.0**；
  `max_refine_blocks` 24576 **未触顶**（层 22 约 16384 块）；关掉 refine 会差 **16.6%**。

**顺带得到一个真实但不可利用的细节**：合法 oracle 找到了一个 **operand 误差完全相同、gain 低 2.15%**
的编码（0.5340 → 0.5225）。即 **"operand 等价"不等于"输出等价"**，tie-breaking 对输出有影响；
但当前编码在 tie 上恰好更优，oracle 站在更差的一侧。

**裁决**：V 的编码在"给定尺度结构"下**处处已最优**，残差是该表示法的表达能力上限。

## 4. 为什么三面墙是同一面

三条线的阻碍看起来不同，实质是同一个：

> **输出误差的结构需要跨 API 的信息（注意力概率 P），而判题器分别、独立地调用 Q/K/V 三个 API。**

- Q/K 主线：`g_Q` 住在 `K_hat` 的行空间 → 需要另一 API 的输入；
- V 侧：输出权重是输入相关的 `P`，校准期能编译的权重在 head 内是常数、必然约掉；
- 而这个"独立调用"**不是仓库自设的规矩，是判题器的调用方式**——动态 API 拿不到输入相关的跨 API 通道。

因此 0.80 的缺口不是"某个机制没找到"，而是**在"解码格式不变 + 动态 API 独立"这两条约束下，
三个 operand 的表达能力已经被榨干**。

## 6. 错误清单（本轮我改正的五处，逐条留档）

**这不是附注，是报告的一部分**——用户问过"你的检测确定正确吗"，答案是"不确定过，且不止一次"。

| # | 缺陷 | 如何被发现 | 处置 |
|---|---|---|---|
| 1 | 闸门 0 的 surrogate 用**未旋转**的 `Q_ref` 比旋转后的 `Q_hat`，测的是 gauge 方向而非量化误差 | 自查（用户质疑后逐条复核） | 改用部署 gauge 内的 `rotate(Q_ref)`，重测；**结论不变**（差 ≤0.003） |
| 2 | V 结论把"state 字段"当作"机制自由度"，据此断言"可动空间≈0.4%" | 自查 | 撤回；墙归位到"输出判据需要跨 API 的 P" |
| 3 | 格式下限脚本**广播维度退化**，给出假的"逐位相同" | 与验证脚本结果矛盾 | 重写；旧 JSON 已删除 |
| 4 | **float32 求和的分辨率**吞掉 162 个元素的微小改动 | 加内部一致性断言后暴露 | 改用 float64，真相是"等距并列" |
| 5 | lv2/lv3 的 oracle **逐元素取 min**（非法：格式要求组内共享），得出假的 **58% headroom** | 合法版本给出 0.00%，两份脚本对同一量矛盾 | **撤回 58%**；不合法脚本改为 fail-fast，产物删除 |

**第 5 处最危险**——我一度据此准备重开 V 卡。抓住它的方式不是更聪明，
而是**写了第二份独立、粒度正确的实现**，两份对同一量给出 58% 与 0.00%，才逼出定位。

**方法论结论**：在这个子问题上，"再测一次"不等于"更接近真相"——同一套错误假设可以稳定地产出
自洽的错数。可信的纠正来自**独立实现 + 对同一量的交叉比对**。

## 7. 对 0.80 的最终判断与选项

**判断**：在"解码格式不变 + 动态 API 相互独立"下，**0.80 不可达**。
Q/K 做满 0.7204、V 做满又到不了——不是机制缺失，是表达力被榨干。

**剩下的选项（均需明确授权，我不自行扩大）**：

1. **改变动态端可见信息**——让 V（或 Q/K）拿到按输入计算的注意力统计量。
   这触及"判题器分别独立调用 Q/K/V"这一**结构性**约束，不只是仓库规矩；可能不可行，需先论证。
2. **改表示法本身**（`lv2`/`lv3` 的结构、或解码格式）——**说明书未禁止**（§2.4 注），
   但会改变与官方解码器的兼容边界；按仓库纪律属"改变官方解码格式"，需要单独授权与论证。
3. **换指标**——若 0.80 不可达，本地面板的优化目标应重新定义（例如改为"在允许方向上取到最优"）。

**建议**：连续五处测量缺陷说明我在这一子问题上已进入"测一次错一次"的状态。
在拿到新方向或新授权之前，**继续加测量的边际价值为负**——只会增加噪声与自洽的错误。
