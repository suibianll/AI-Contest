# V 侧结论：授权范围内到不了 0.80

> 前置：AGENTS §3 带日期例外条款（用户授权校准期 V 码分配，解码格式与动态约束不变）；
> 审计过程见 [`v-card-audit.md`](v-card-audit.md)。2026-09-10。**全程 CPU，未训练、未跑 shard、未出候选。**

## 1. 天花板是真的（已测）

| 反事实（72 例） | gain |
|---|---:|
| 现在 | 0.5340 |
| **V 完美** | **0.8115（≥0.80）** |
| Q 与 K 同时完美 | 0.7204（<0.80） |

V 是唯一通路；层 22 单靠 V 可从 0.3015 到 0.9634。

## 2. 但这条通路在"校准期码分配"的授权范围内打不开

`_build_v_state` 给 V 的全部自由度就是六个 state 字段，逐个查完：

| 字段 | 实测 / 核对结果 |
|---|---|
| `importance` | **完全不起作用**：`normalized_error = Σ(err²·imp)/Σ(x_abs²·imp)`，imp 逐通道常数 → 约掉 |
| `max_refine_ratio` | 经 `_loss_capture_ratio(target=1.0)` **本就是 1.0**，×N 被 `min(...,1.0)` 夹住 |
| `max_refine_blocks` | 24576，**未触顶**（层 22 约 16384 块） |
| `error_threshold` / `accept_margin` | 常量，只用于拒绝 refine 提案 |
| **`search_offsets`** | **唯一自由的字段**，常量 `(-1,1,2,3,4)` |

**且 refine 本身是权重盲的**：接受判据 `best_loss`（`Σ err²·imp`）作用在同一个块上，
权重在比较两边相同而约掉；`_REFINE_RANK_BY_ABSOLUTE` 的排序只在预算触顶时生效，而预算未触顶。

## 3. 结论：V 的码已经在该机制内做到穷举，残差是结构性的

- 关掉 refine：E_v 0.08443 → 0.09843（**+16.6%**）→ refine 是活的、覆盖全部块；
- 基准打包（无 refine）0.09843 与标准编解码 0.09714 基本同档；
- 即在当前 baseline + 偏移窗口内，**V 已经做到逐块最优**，而 **`importance` 与排序都不参与任何决策**。

**残下的误差来自两处，且都不在"校准期码分配"的授权范围内：**

1. **偏移窗口之外**：`search_offsets` 是唯一自由字段，但 `_DYNAMIC_OFFSETS` 的注释记录前人已用 oracle
   诊断测过扩展窗口（"captures 99.6% of exhaustive gain"、"edge-extension hill-climb cannot reach it
   across binades"）。**收益上限约 0.4%，量级差 60 倍以上。**
2. **块间交叉项**：输出误差是 `||Σ_k P[:,k]·delta_V[k,:]||²`，**跨 key-token 存在交叉项**，
   逐块贪心在数学上就不是全局最优。要吃到这一项需要**跨 token 的联合求解**——
   那是改动态编码器的算法，不是"校准期码分配"，且会改变动态路径的执行结构。

## 3bis. 论证更正：可动空间比我先前写的更大，但墙换了个位置（2026-09-10）

**先前写法（不完整）**："六个 state 字段里只有 `search_offsets` 自由，故可动空间≈0.4%"。
**问题**：把"state 字段"当成了"机制自由度"。授权写的是**校准期 V 码分配/求解算法**——
而编码器的算法就在我们的源码里，只要产出的仍是合法五字段、官方解码器读得动，它就是可改的。
所以自由度不止那一个字段。

**换位置后的真墙（更硬，且是结构性的）**：

> 任何**输出感知**的判据都需要注意力概率 P；而 P 由 Q/K 决定、随输入变化，
> **V 的动态 API 看不到**（跨 API 输入禁令）。
> 任何**校准期编译好的**权重（例如现有的逐 head `E[A²]`）在同一 head 内是常数，
> 在逐块判决 `Σ(err²·w) / Σ(x²·w)` 里分子分母同约——**必然不起作用**。这不是实现缺陷，是结构。

因此：V 要吃掉那 87%，必须知道"哪些 key token 被关注"，而那正是它在动态端拿不到的东西。
这与闸门 0 否掉 Q/K 主线**是同一堵墙的两个面**：输出结构需要跨 API 的信息。

**但有一处例外值得单独记录**：V 的编码调用**一次看到整个 V 矩阵**（所有 token），
所以"跨 token 的联合求解"在单次调用内是可行的——只是它的**权重**仍然只能来自 V 自己，
而 V 自己的跨 token 耦合在纯 operand MSE 下不存在（operand MSE 逐块可分，联合求解无对象）。
要吃跨 token，需要 P。

## 4. 对 0.80 的如实交代

- **在现行授权的范围内（校准期 V 码分配、格式与动态约束不变），0.80 不可达。**
  唯一自由字段的收益上限约 0.4%，而 Q/K 侧合计上界 0.7204。
- **要接着走，需要一次新的、更大的授权**：允许改动**动态 V 编码器的求解算法**（例如跨 token 联合码分配）。
  这会改变动态路径的执行结构（是否满足"动态无候选循环"需要单独论证），
  与本次"校准期码分配"不是同一件事。**我不自行扩大授权范围。**
