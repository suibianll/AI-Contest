# L-R2 COST_HOLD 后继评估：缓存/统计量复用可行性与 T 依赖清单

> 日期：2026-09-07。侧：Linear。run_id：`repair-r1/l-r2-followup`。

## 1. 各量是否依赖 T（禁止复用过期 Gram/Hessian）

| 量 | 依赖 T | 依据 |
|---|---|---|
| `X^T X`（校准激活外积） | **否** | X 是父部署坐标（smooth/perm/hadamard 后），与 T 无关；每 state 预计算一次即可 |
| `gram_full = T^T (X^T X) T`（64 块对角收缩） | 是 | 每步需做 T 双侧收缩（896/4864 宽，块对角 64×64） |
| weight `H_inv`（cholesky inverse of gram_full） | 是 | 依赖 gram_full → 每步重算（0.002–0.05s，可接受） |
| weight 五字段编码（`_gptq_quantize_weight`，含 refine） | 是 | W T^{-T} 每步变化 → **每步 0.44–2.2s，不可复用** |
| activation `H_inv_a`（from Q(W T^{-T}) 输出 gram） | 是 | 依赖当前权重量化 → 每步重建（0.002–0.05s） |
| activation 五字段编码（含 refine） | 是 | X T 每步变化 → **每步 0.17–0.9s，不可复用** |

## 2. 预计算/批处理的净收益

- `X^T X` 预计算：从单步 0.002–0.05s 中省下 gram 组装，收益 < 0.05s/step，
  **约单步总成本（0.62–3.24s）的 2–8%**，不改变 COST_HOLD 结论。
- weight/act GPTQ 是主导成本（>80%），两者都依赖 T 且语义上必须每步
  用当前 T 重建部署坐标编码——无免费复用、无法批处理（块序依赖当前码）。
- 结论：**无足够增益的实现方案**；按 L-R2 决策"只有具体实现方案成立才
  运行"，本评估不改写求解规则（减步数/扫 rank 均禁止），COST_HOLD 保持。

## 3. 出路（不改变硬前向语义）

1. 换一个不依赖"32 步完整硬前向"的解析/闭式求解（必须另立机制卡预注册，
   不能改当前卡规则）；例如：如果能用 `X^T X` 与 W 的解析式表达 T 的最优
   块对角旋转（避免逐层训练循环），则成本与 L-R2 测的逐层训练不同。
2. 若协调者批准降低步数或只训部分 state，需重新注册并说明方案，不能现场
   "减步数"冒充原卡。
