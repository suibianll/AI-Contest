## 这张卡是什么：把已官方定价的 +29 落到当前根上

A-GR1（一般非对称互逆矩阵残差 M=I+N）的官方价值已被侧隔离**测出**：
`standard-linear_v234-attn` = **14455 / 263.7s**，相对同口径 v195 侧基准 `14426/243s` 为 **+29**。
它是继 C76.4（+84）、A1（+60）之后 Attention 侧第三大官方正向机制，也是 2026-09-10 这条线
唯一的官方正向 Attention 候选。

**但它从未落到完整根上。** v234 的父是 v230，而根此后晋级为 v231。本卡只做一件事：
**把同一块 A-GR1 重新挂到 v231 根上**，从而对"完整包形态"取得一次官方读数。

机制本身**一个字节没改**——这一点下面用机器证据证明，不是自述。

## 证据一：结构上，候选与 v234 逐字节同构

两条独立的字节级测量（`cmp` / `diff`，不是自述）：

1. **纯追加**：候选前 505762 B 与 v231 根 `cmp` 完全相同；余下 15193 B 是 A-GR1 块。
2. **与 v234 的差异 = v230→v231 的差异**：

```
diff(v234归档候选, 本候选)  ==  diff(v230根, v231根)   ← 同一个 hunk
```

唯一 hunk 就是 Linear 侧的 `_EM1_PASSES = 1 → 2` 及其注释。而 `_EM1_PASSES` 全文件只在
**Linear 路径**被引用（pass 循环 `for _pass in range(_EM1_PASSES)` 与一个审计字段），
Attention 段不读它。

配合 shard0 运行时账本里 `hif4_calibration_and_quantize_weight: 0 calls`（attention-only
不调用任何 Linear API），得到推论：**本候选的 Attention 行为与 v234 必然逐位相同**。

## 证据二：六 shard 独立证实了上述推论

推论必须被实跑证伪，不能用它替代证据。六 shard 结果：

等权 `+0.003845`，**21 / 3 / 48**。

**与 v234 的六 shard 逐项完全相同**——不只是 Δmean，连 L1、delta_tail、计数都一样；

**这张卡因此是"同一 Attention 行为 + 新 Linear 父"，不是新机制证据。** 如实登记，
不把复现当增益。

### 一个执行细节（会影响以后所有 Attention 卡）

评测器 `--stop-after-nonpositive` 默认值是 **2**。本候选的 shard0/shard1 恰好都是精确零，
所以默认参数下运行会在 shard2 前停住，**正好藏掉唯二两个真正 arm 的层（15/22）**。
本次显式传 `6`。v234 当时也传了 6；这条值得写进 Attention 侧的执行习惯。

## 时间：预登记规则，其超时分支已由官方回传坐实

A-GR1 有校准期训练成本。侧隔离形态测到 **+20.7s**（相对 v195 侧），而当前完整根是
**291s / 300s，只剩 9s**。

**本卡归档之后**，用户回传了兄弟卡的结果：**v234 完整包（v230 根 + 同一块 A-GR1）
官方 `TIMEOUT (>300s)`**（见[超时记录](../../logs/execution/2026-09-10-v234-agr1-official-timeout.md)）。

这条证据直接落在本卡上：

- A-GR1 的额外时间在**校准侧**，是**机制属性**，基本不随 Linear 父变化；
- v231 只比 v230 快 **1s**（291s vs 292s）；
- 因此本卡预期总时约为 v234 的 **−1s**，**只有 v234 的超限幅度 ≤1s 时本卡才可能进限**。

**这不改变本卡事前固定的晋级规则**，只是把它**超时分支**的可能性推成了主要分支。
它**不能替本卡下结论**——本卡是不同实现（不同父）、且超限幅度官方从未给出。

**不写任何官方秒数预测**（超限幅度未知，且侧时间与完整包的关系从未标定）。

**v236 已超时**，见[超时记录](../../logs/execution/2026-09-10-v236-agr1-on-v231-official-timeout.md)。

这一条**回答的正是上面那个唯一未知量**。归档时写明的条件是“只有 v234 的超限幅度 ≤1s 时本卡才可能进限”；
现在两次完整包超时构成**双向封闭的区间**：父差只有 1s，所以不存在“换个 Linear 父就能过”的空间。

信息增量不是“这版也没过”——那在归档时已近乎预期——而是
**A-GR1 的校准侧代价与 Linear 父的近旁替换无关**，把归档时按机制属性写下的判断变成了实测事实。
代价在校准侧（6 层 × 32 步 Adam），部署动态路径没有新增算子。

### 由此得到的 Attention 侧判断

**卡住 A-GR1 的是时间余量本身**（需要约 20s，手上只有 9s），不是父、也不是机制。
所以 Attention 侧最高价值的动作**不是再出 A-GR1 变体**（该卡自身规则禁止缩步/缩窗/减候选
——那是削弱机制），**而是先把秒数腾出来**，再落地 A-GR1。这与 Linear 侧正在做的
运行成本回收（v233 L-TF1 已官方定价 −4s、v235 L-AD1）是同一个方向。

本归档候选的 attention-only 运行是校准缓存命中，故其 api 秒数为纯计分口径，
不跨缓存状态比较（AGENTS §5）。
