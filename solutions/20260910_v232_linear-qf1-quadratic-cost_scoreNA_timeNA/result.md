## 机制：父根的局部代价不是它以为的那个量

`_em1_dynamic_descent` 给 8 个 pm1 候选定价用的是

```python
quadratic = torch.einsum("krba,bij,krbj->krb", delta, local_gram, delta)
```

两个求和指标各自只出现在一个操作数里：`a` 只属于第一个 `delta`，`i` 只属于
`local_gram`（只有 `j` 同时属于 `local_gram` 和第二 个 `delta`）。`a` 与 `i` 从不相遇，
所以收缩出的是

```
(Σ_a δ_a) · Σ_j (Σ_i G_ij) δ_j   =   1ᵀδ · (colsum G)ᵀ δ
```

而不是 `δᵀ G δ`。修正版让第一个操作数按 `local_gram` 的**行指标**索引：

```python
quadratic = torch.einsum("krbi,bij,krbj->krb", delta, local_gram, delta)
```

**这不是"等价重结合"。** 换掉耦合的指标是换公式，不是把同一个和换次序。父根自己在
`solution.py:1983` 就用 `"krbi,bij,krbj->krb"` 收缩 `e^T H e`——修正式是文件自己的写法，
不是新发明。

真实候选集让缺陷**精确退化**：8 个 pm1 候选全是单坐标的
（`element_index=[0,0,1,1,2,2,3,3]`，每行 mask 只有一个真），所以 `δ = c·e_m`（`c=±0.25`），
两种写法分别等于 `c²·colsum(G)[m]` 与 `c²·G[m,m]`。父根一直在用**列和**给候选排序。

## 修正后，接受判决的代价就是目标差本身

`J(X)=‖(X−T)Ŵᵀ‖²` 对 `X` 是二次的，所以

```
J(x+d) − J(x) = 2·∇J·d + dᵀGd
```

是**恒等式**而非二阶近似。独立参考（float64 稠密矩阵乘，直接对 `J` 取两点差值）测得
`Q3`：修正式相对误差 `4.767e-15`（fp 地板），父式 `5.439e-02`。

## 缺陷的诚实边界

`Q5` 证明父式**可能反号**：`G=[[1,-2],[-2,10]]` 特征值 `0.5756/10.4244` 是正定的，
但第 0 列列和 `= −1`，于是 `δ=[1,0]` 时真代价 `+1.0`（该拒绝）而父式报 `−1.0`（会接受）。

**但真实数据上这件事没有发生。** 真实 layer0/q 的 **0/2560** 个局部 Gram 列和为负
（`local grams with a negative column sum: 0/2560`）。这块数据上缺陷的实际后果是
**量级误排**：81920 个提议槽位中 5.94% 选了不同候选，接受判决 5491 处不同。
只报反例会夸大缺陷，只报计数会掩盖缺陷，两者都记。

## 候选构建：改动由机器测量

`build.py` 不手写覆盖函数，而是从父根字节里切出 `_em1_dynamic_descent` 的源码、
替换一个子串、追加回去。于是"唯一改动"是**测出来的**：脚本统计两段文本的逐字节差异数，
不等于 1 就拒绝构建。本次 `extracted_function_differing_bytes = 1`。

`_em1_dynamic_descent` 由父根的 hook 在调用时从模块全局解析（`co_names` 含该名字），
所以追加定义遮蔽父定义，父根两个 hook 一行未碰。候选里唯一的变化是"父定义变成死代码"。

## 时间：不增加

改的是一个字符，`einsum` 的操作数形状、步数、循环结构一个未变；
`build.json` 的 `extracted_function_differing_bytes = 1` 就是"零新算子"的机械证据。

- **受控测量**（shard0 同进程配对，同一份校准、交替计时）：
  候选动态 API `42.2156 s / 56 calls`，基线 `43.1058 s / 56 calls`——候选快 0.89 s。
- **跨进程对照**：候选 `42.2156 s` vs 归档基线 `41.934 s`——候选慢 0.28 s。
- 两者**夹住零**。六 shard 跨进程动态差从 `−3.22 s` 到 `+2.16 s`，噪声比任何可归因于本改动的
  差值大一个量级。

绝对 `api_total` **不可比**（候选新 SHA 冷启校准缓存，归档基线走缓存命中），不作为计时证据。
**不写官方秒数预测**：改动按构造时间中性，合理陈述是"应当仍是父根的 292 s"，
但本地测量无法定官方秒数，计划已退役本地时间预测。

## 裁定：REJECTED（官方 TIMEOUT）

336 个配对 case 中 284 改进、4 回退（合计为增益的 0.08%）、48 为 out-of-scope；
六 shard 全正。机制是**正确性修正**：父根的局部代价不是 `δᵀGδ`，修正后接受判决的代价
与真实目标差一致到 fp 精度，本地零可测时间成本。

官方回传（2026-09-10 用户）：**TIMEOUT (>300s)，REJECTED**，精确秒数/分数未知。本地
"应当仍是父根 292 s"的陈述没有转化为官方计时——本地时间测量不是官方时间预测（计划已
退役本地时间预测）。一次超时不反驳该正确性修正本身，只关闭此实现代表；根现为 v231
（18518/291s），本候选不缩步/缩窗/改候选数重试。

本地工具的 `reject` 是它自己 `delta_mean > 0 and L1 < 0.02` 的**小趋势筛选门**，工具自身
政策写明"local eligibility is not promotion"，本归档不主张本地通过。

**血统**：v232 是 v230 的后代，**不含** v231 的 K=2 机制；两者不是叠加关系，
其本地 Δ 不可作为官方预测相加。Attention 半边与父根完全一致（v195）。
